当前guided完整源版本已由用户明确审核通过，身份见[源版批准记录](design-approval-guided-20261031.json)；其他页面按[全页与状态闭包](all-page-design-coverage.md)逐项对齐。设计源批准、独立参照、真实组件和正式包验收分别记录；原29个阅读/配置增量状态继续保留，不能代表整套页面。

工作从[现行文档首页](../README.md)开始，优先级见[current-phase.json](current-phase.json)。已授权范围内自主实现；产品范围、设计确认、技术契约与运行验收分别处理，不能互相提升。

## 2. 编码前：一条工作项形成完整追溯

每个可验收工作项必须包含以下链条，允许一对多。页面任务采用整页交付合同：完整功能旅程、页面区域/操作清单、真实接口及待实现依赖、状态与真实client视口、各层用例和完成证据必须同时列明；控件切片完成不关闭父页面。具体任务以[当前整页交付计划](current-client-alignment-plan.md)为准：

**需求/专项验收 → 设计页面及状态 → 架构模块/组件 → 实现任务 → 验证用例 → 运行证据。**

| 必填项 | 要求 |
| --- | --- |
| 需求及验收 | FP、相关原 REQ、AI-CFG、MC、GL、学习扩展；不适用项写明原因，不捏造 ID |
| 设计定位 | 页面入口、选择器/锚点、操作旅程、正常与异常状态、对应截图及其确认状态 |
| 实现归属 | M 模块、C 组件、Owner、审阅角色、公开契约、允许修改路径、复用点 |
| 依赖 | 前置任务、所需 B 门禁与输入资源；明确已有端口、待设计合同、待实现端口，未实现依赖不能标ready；区分可并行开发与页面完成/发布依赖 |
| 可观察结果 | 用户从哪里操作、得到什么结果；含取消、失败、重试、空态及迟到结果等适用分支 |
| 验证与证据 | 用例 ID、方法、执行环境、必要真实输入、证据位置和完成条件 |

例：目标切换工作项可追溯 `FP-03/05 → GL-15 → #app-dialog / .gl-switch-review → gallery.html#48-window-switch-confirm → M02/M12/M13/M14 → C13/C14/C15 → 对应实现任务与运行记录`。这里仅示范映射，不宣布该工作项已通过；真实用例仍需覆盖新 Core、取消、复用、切换失败与显式选流。

新增配置和首版细节必须补入统一追溯表，不能靠某个旧任务“标题类似”就视为覆盖。原55任务、111回归保留身份；缺少的任务/用例新增编号。当前计划检查器不支持 FP/AI-CFG/MC/GL/M/C/B 的完整追溯，扩展前不得据其通过宣称新首版覆盖完整。

工作项 `ready` 表示已存在的端口、需要的合同/实现、设计映射和输入前置均具备，不等于用户已授权启动整个产品。明确要求用户review的新计划，在该review完成前保持pending_user_review；既有源版批准不被重置。相关设计尚待评审时，先完成对应设计确认或推进不依赖它的工作。正常实现细节由 Owner 在已授权范围内处理。

## 3. 实现时：边界和复用必须可检查

| 约束 | B0 后的检查方式与人工审阅重点 |
| --- | --- |
| `windows → features → ui/patterns → ui/primitives → tokens` | 导入限制及组件审阅；跨 feature 通过公开接口，不复制编辑器/阅读组件 |
| `src-tauri` 组合；`app-infra → app-core` | Cargo 依赖及源码导入检查；业务核心不依赖 Tauri、数据库、网络和 FFI |
| UI 只走 application-port 与生成 DTO | 阻止页面直接 HTTP/SQL/Keychain/注入；DTO/schema 生成后检查漂移 |
| 新 Core 独立，broker 同位数 | 资源锁、ABI、七回调、架构与逐文件 hash；不静默回退旧 runtime |
| 词法 worker 与 Hook/模型隔离 | 依赖与进程边界检查；断网内置资源、故障隔离和 Unicode 对齐实测 |
| Rust 业务状态权威 | 状态转换、revision、取消/迟到/重连行为测试；多窗不各自维护一份运行配置 |
| 同一设计 token 与 SVG 图标族 | token 生成一致性、样式审阅与截图对照；不引入另一套默认主题或任意强调色 |

当前已建立TypeScript AST、Cargo依赖、技术锁、权威源指纹和实际编译检查；DTO/token生成漂移、release fixture导入图等仍需随具体产品实现接入。扫描规则只能发现部分违规；端口职责、状态语义和复用合理性仍需独立审阅。审阅者应与实现者分开，可以是另一位协作者或审查代理，但审查意见必须有文件/行为依据。

## 4. 验收时：九类门禁统一执行

以[工程门禁](engineering-gates.md)和[门禁设计](gate-validation-design.html)为现行执行规则。固定代码命令和实际diff决定检查，普通问答不全量测试；Codex hooks、手动、Git和CI复用同一执行器。真实编译、生产端口/存储、原生与四游戏分别验证。

视觉G09为独立正式门禁，只给一份设计/实现统一报告；同尺寸/数据/状态捕获，用户或指定审阅人明确确认当前范围，机器消费确认记录。待审、拒绝、缺图、过期均不能宣称对齐/准出；等待人工不无限续跑。旧源版批准、旧像素原件和失败保持历史身份，不重新拍图覆盖旧结论。

32组门禁有效性计划和每次实际运行分开；规则测试、真实CLI、真实Codex事件不能相互冒充。所有脚本错误、零断言、必选skip、错原因拒绝和输入漂移必须检出。

| 变更审阅 | 只改允许范围；相关行为/静态检查通过；架构边界与复用审阅通过；涉及 UI 的视觉差异有结论 |
| 工作项完成 | 承诺的完整用户流程、区域排布、异常/恢复和适用层均有通过证据；失败修复并重跑。部分控件/旧Tab退役或编译成功不能关闭整页；缺项保持部分实现/未完成 |
| 产品发布 | B0～B5 按[研发基线](../architecture/first-product-engineering-baseline.md)逐项满足；同一最终包、资源与环境的产品回归通过；许可证和来源齐全 |

B0 除依赖/资源冻结，还要完成新增追溯映射、自动检查接线、确认截图的保存方式及旧草稿隔离。B1 是新 Core 正式包原文闭环；B2 是阅读与数据；B3 是翻译与配置；B4 是本地学习；B5 是完整首版正式包回归。允许按已有依赖图并行工作，不跳过所需发布门禁，也不将 B1 单独称为完整首版。

四游戏仍逐款完成 SR、MO、Never7、サクラノ詩 10th，不测 Ever17。正常字幕变化、译文、历史和学习结果必须与对应输入、同一最终包身份关联；Core C++ 探针、旧 Reader、网页报告不使新包用例自动通过。

## 6. 变更规则

现行文档采用覆盖更新：修改对应原章节、现状表和交叉引用，移除重复或失效解释，不向文件末尾追加日期版“本轮/最新”说明。历史OpenSpec、批准源/图、原计划和执行原件保持原身份，只作追溯。结构守卫检查日期追加标题、重复H2主章节及已退役根原型入口；现行设计链接以已批准组合为准，历史入口通过追溯索引读取。业务语义一致性仍由非作者逐项核对；不得把结构通过称为文档事实自动正确。

- 已确认范围内的代码组织、缺陷修复和符合契约的普通实现，由 Owner 执行并记录验证；不增加逐次用户审批。
- 增减产品能力、改变确认过的交互/视觉、公共协议、技术栈或跨模块职责，先给出原因、受影响需求/页面/模块/用例及迁移/回归计划。需求改 PRD，交互改设计，架构决策改 ADR；按影响取得对应确认后再实施依赖部分。
- 不改原始快照。基线更新产生新 revision 和旧→新差异记录；代码作者不能在同一操作里无审阅替换规范/截图并据此声明通过。
- 缺资源、登录、真实凭据等外部条件时保留 `blocked` 原因，继续其他独立工作；不以临时样本绕过已承诺的验收。

## 7. 计划、运行和证据分开

原 `requirements.csv`、任务 CSV、回归 CSV、MC/GL 验收矩阵描述计划与验收定义。现有重建任务与回归检查器要求其快照保持 `ready/planned` 与 `not_run`；本规则将历史定义与运行分开，不能直接将这些历史计划改成结果表。

每次运行按[产品回归规则](client-regression.md#每次执行的证据目录与状态规则)另建 `run_id`，记录 baseline/iteration/work-item/test ID、实际客户端源码/dirty 身份、包 SHA-256、Core commit/ABI/架构、语言资源版本、环境、步骤、实际结果、缺陷和证据相对路径/hash。多平台与不同游戏版本分开。当前使用真实Git提交及dirty文件指纹；首次导入前的历史记录保留原来源身份，不补写虚构commit。

`passed` 必须有实际执行和证据；`failed` 留缺陷及重跑；`blocked` 留外部阻塞；未执行为 `not_run`。修复后生成新的运行记录，不抹掉失败历史。候选包变化需要按影响重跑，发布汇总不得拼接不同包的旧结果冒充同一正式包通过。

## 覆盖与发布执行闭包

[逐项逐层覆盖](reading-window-test-coverage.md)从RW权威CSV读取身份；修改设计/PRD必须补对应层/状态。浏览器设计、真实组件、真实数据管线、语言worker、原生窗口与四游戏不相互继承。登记、实际命令、nonce、源码与工件身份、断言及截图须共同校验；发布还需[153个执行组合](release-execution-evidence.md)。已存在设计、部分真实组件/存储和有限原生执行器，各自能力范围独立；当前guided仅注册4态有限真实React能力，完整逐态与Native捕获仍未齐；未覆盖层保持not_run并拒绝发布。
