# 迭代卡模板

按[迭代执行规则](iteration-governance.md)使用。复制到 `docs/development/iterations/<iteration_id>/plan.md` 后填写；本模板不是已经开工的迭代。

## 迭代身份与授权范围

| 字段 | 填写内容 |
| --- | --- |
| iteration_id / baseline_id | 本次唯一 ID；引用基线 revision 与指纹 |
| 用户授权范围 | 对应指令与本次交付；文档/实现/实测分别写明 |
| 目标 / 不在本次范围 | 可被用户观察到的结果及范围边界 |
| B 门禁 / 前置任务 | 哪些输入已满足、证据在哪；开发/发布依赖分别写 |
| 主责 / 独立审阅 / 验证角色 | 人或协作者；复用模块涉及谁 |
| 源码与产物身份 | Git commit/dirty；未纳管时用来源与指纹，不能虚构版本 |

## 工作项追溯

每个工作项重复下面表格。不适用项写原因；缺项先补齐，不用“同上全部覆盖”替代明细。

| 字段 | 填写内容 |
| --- | --- |
| work_item_id / 实现任务 ID | 保留既有 M1/M2/M2-L/M3 ID，新增项明确编号 |
| 产品依据 | FP / REQ / AI-CFG / 学习扩展及原文条款 |
| 专项验收 / 测试 | MC / GL / CR 或新增测试 ID |
| 设计 | 当前入口、锚点/选择器、交互步骤、正常/空/等待/失败/取消状态 |
| 视觉依据 | 基准截图与 hash、确认范围、视口/主题/scale/字号 |
| 模块 / 组件 / 契约 | M / C ID、端口/DTO/schema、状态归属 |
| Owner / 审阅角色 | 一个明确主责；跨模块需要的审阅 |
| 修改范围 / 复用 | 允许路径、公共实现、禁止跨越的边界 |
| 前置与阻塞 | 区分已有端口、待设计合同、待实现端口和真实资源/环境；目标接口不当成已实现，依赖未齐不标ready |
| 整页交付合同 | 完整用户旅程、首屏/辅助/折叠/固定区及按钮清单、实际client宽窄/长文/200%状态；各区域对应组件/数据权威 |
| 可观察结果 | 从实际入口如何操作、看到什么，适用负例与恢复 |
| 验证计划 | 静态/行为/Playwright/原生正式包/真实服务/游戏分别列明 |
| 完成条件 | 整页所有承诺功能、排布和适用层需通过哪些用例，证据位置；部分实现与父页面完成分开，不得预填结果 |

如需机器可读追溯表，采用同一含义的 `traceability.csv`：

```text
work_item_id,task_id,baseline_id,gate,requirement_ids,acceptance_ids,design_refs,module_ids,component_ids,owner,reviewer,allowed_paths,depends_on,test_ids,acceptance,implementation_status,evidence_index
```

只在真实需要时新增执行工具，不预先创建空产品模块。该格式目前是约定，尚无自动完整性检查器。

## 变更与审阅记录

现行规范直接覆盖对应章节和状态表，同步相互引用；不追加日期尾章制造多套当前规则。计划review、设计源批准、源码审查、实际运行和产品完成各自说明。

- 与基线的差异、原因及影响；普通实现细节和规范变更分别说明。
- 受影响 PRD/设计/ADR/契约/测试；需要确认的范围及实际确认来源。
- 架构依赖、状态归属、复用与异常路径审阅；意见、修复和剩余限制。
- 有 UI 时附候选/基准/差异图；不得自动覆盖已确认图或放宽阈值。

## 执行结果与交付

每个执行组合生成独立 `run_id`，按 [回归证据规则](client-regression.md#每次执行的证据目录与状态规则)记录实际结果。任务计划和运行结果分开；原始私人游戏证据不默认入提交或分享包。

| 项目 | 实际填写 |
| --- | --- |
| 包、Core、资源、环境身份 | 客户端包 hash、Core ABI/commit/arch、辞书版本、平台/游戏/语言 |
| 实际检查 | 命令/方法、时间、结果，未执行原因 |
| 视觉与原生行为 | 各自结果与截图/记录；不混为一个通过 |
| 用例结果 | passed / failed / blocked / not_run；缺陷与重跑关联 |
| 证据 | 相对路径、hash、与工作项/用例/包的关联 |
| 最终状态 | 实际完成项、未完成项、风险与支持范围；下一门禁 |

完成报告以实际交付和验证为准。没有执行证据时不写“已通过”，没有用户提交/推送授权时不执行相应动作。
