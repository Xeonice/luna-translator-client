01

先明确：这次要证明什么

门禁有效的四个条件

  1. 合法修改能够正常通过。
  2. 约定违规由正确规则拒绝。
  3. 实际入口确实触发检查，不能只调用模拟脚本。
  4. 漏跑、过期和检查器故障不能被算成通过。

保留简单的审核方式

  • 门禁执行只给一张结果表。
  • 视觉只给一份设计稿与真实实现并排的统一报告。
  • 原始日志由工具留存，按需查看。
  • 不新增多轮像素评分、叠图或参照审批流程。
本页已获用户明确批准并授权实施。本轮实施门禁程序、Codex hooks与有效性验证；不修改客户端、不替换应用、不重启游戏、不提交代码。本页不覆盖已有设计批准或历史失败记录。后续实施须建立 OpenSpec 变更、明确修改路径，并覆盖更新受影响的现行规范。

用户最近明确要求的简化视觉流程优先于旧文档中的复杂流程；旧批准源、截图和原始执行记录保持历史身份，不用于自动补成本轮通过。

04

触发、检查与放行是三件事

实际事件

Codex 工具调用、工作项交付、Git 或候选包验收。

统一调度

按真实改动与依赖图，选择必要规则和测试。

执行与核对

同一规则执行器检查，核对结果身份与观察点。

可见结果

一张结果表；决定能否操作、交付或发布。

触发点要做的事真正阻断什么避免误用
SessionStart加载当前工作项、批准范围与待验证状态；恢复会话时读回。本身只提供上下文；缺少合同由写入前和交付检查拒绝。不在会话启动时编译或回归游戏。
PreToolUse对可解析的文件操作、依赖变更及打包替换前置条件进行检查。明确返回拒绝时，阻止对应受支持的工具调用；核对文件未变化。不依赖命令字符串猜测任意 shell 行为；无法预判则记录覆盖限制，事后查真实改动。
PostToolUse读取实际变更；快速边界检查；登记需重跑项。反馈违规、标记当前修改未通过；交付检查独立拒绝。已执行的写入不会被 hook 撤销；异步检查不能作为即时操作阻断。
Stop根据实际改动与工作项状态检查验证结果；必要时批量执行。缺少可补的检查时要求继续；正式交付由项目命令再次判定。每轮结束都会触发。只读问答直接结束，不因历史待办反复全测。
UI 捕获完成 / 人工视觉确认更新同一报告，将 G09 标为待审；明确确认后核对当前身份并重算门禁。未确认、拒绝、缺项或过期时，统一交付命令拒绝页面完成和产品准出。等待人工只报告 blocked，不无限重跑截图；允许安装待验候选供检查，但不能宣布验收通过。
提交 / 推送 / PR恢复 Git 后：提交前快检，推送及 PR 跑工程与受影响测试。Git hook 拒绝提交 / 推送；远端必需检查拒绝合并。目前未接入远端保护；本地 hook 可被绕过，不作为唯一依据。
打包替换 / 阶段准出打包核对工程与包体，安装后验基本流程；阶段准出核对全部承诺。不合格候选拒绝替换；未完成产品拒绝进入下一阶段 / 发布。允许安装待验候选不等于产品通过；实机回归不挂在每次提交。

Stop 的有界执行规则 拟定

  1. 无实际修改且未请求验收：直接结束。
  2. 有修改：读取实际影响与当前结果，不靠回答里的“完成”二字判定。
  3. 可执行但缺失的检查：要求补跑；同一失败指纹最多自动续跑两次。
  4. 源码或错误变化才重新计算；外部 blocked 或次数用尽时停止重复调度，交付状态仍 incomplete。
  5. 用户中断立即让出控制；子代理只报告自己范围，不能关闭父工作项。

Hook 故障不等于操作被拦住

官方机制中，未信任配置会跳过；部分错误或不支持的返回格式可能让工具继续。不能声称异常总会自动阻断。

项目 verify、打包包装入口与后续 CI 必须独立重算必要检查，拒绝缺结果、错误结果和过期结果。它们保障交付判定，不能倒推此前没有副作用。

所有匹配的全局与项目 hooks 会共同运行，不能假设自己的 hook 能阻止其他 hook 启动。必须验证真实宿主与全局配置共存。

本节平台行为依据：PreToolUse、PostToolUse、Stop、信任机制。项目配置加载与信任需要实施后实际核对，本页不预先授予信任。

05

32 组正反例：具体怎么验证

每组至少一个正例、一个反例。字段边界、平台、工具路径等需参数化执行，不能把 32 组当作固定测试总数。展开查看观察点。

被测门禁的结果与外部验证的结果必须分开。普通违规样本应被预期规则在预期阶段拒绝；变异场景则要证明外部测试能发现门禁失效。每个分支分别定义 expected_gate_result、expected_verification_result 和副作用观察点。任意非零退出、依赖缺失或检查器崩溃都不算正确拦截。视觉反例验证报告准确呈现差异、未获确认时拒绝准出，不承诺自动理解视觉。

06

从规则到真实入口，分层证明

L1 · 规则与协议

在可丢弃样本中调用正式规则函数，验证正例、反例、边界和 hook 输入 / 输出协议。

能证明判断逻辑；不能证明项目 CLI 或 Codex 实际触发。

L2 · 真实项目命令

测试进程启动真实 verify / 子检查器，断言命令、退出码、原因和实际副作用。

必须覆盖根调度器，防止子检查正确但根入口漏派发。

L3 · 真实 Codex 事件

在已信任的隔离测试项目内，经实际 Codex 工具执行合法 / 越界操作与结束轮次。

由外部测试进程核对文件前后值、真实事件及继续 / 结束表现。手写事件 JSON 不算此层。

每组运行的固定步骤

  1. 准备：使用已审合同和有限测试样本；逐分支固定门禁预期、外部验证预期和观察点，记录工具 / 规则 / 样本身份。源目录与正式用户数据只读，数据库用临时库。复制只包含必要文件，不复制游戏或大资源。
  2. 正例：执行真实入口，观察与预期一致。合法修改应放行；测试门禁拒绝能力时，正确拒绝违规本身也是验证正例。
  3. 反例：只注入约定违规或门禁失效，使用相同入口；核对规则、阶段、定位与副作用。普通违规应被门禁拒绝；被损坏门禁若错误放行，外部有效性测试必须变红。其他错误属于测试失败或环境 blocked。
  4. 修复恢复：撤销隔离注入后再执行，应恢复原来的正确判定；合法修改仍可放行，门禁不会永远卡住。
  5. 交叉核验：独立测试进程读取实际结果；不让被测规则自行填写自己的验证结论。合成记录显式标为测试用途，永不写入产品通过。
  6. 记录：每次运行独立目录，保留失败与重跑关系。基准和当前工作区不被自动替换。

故障注入

覆盖检查器异常、超时、非法返回、结果删除、必选测试跳过、源码途中变化、并发串用、hook 未信任 / 被禁用。

内部错误记 failed；真实外部条件不足记 blocked；二者均不授予交付通过。

门禁变异

在隔离副本把拒绝改成放行、跳过必要派发、绕过结果失效判断。原有效性测试必须发现，不能仍然全绿。

只对已定义关键判定逐项变异，不追求没有解释价值的全项目百分比。

07

一张结果表，两种完成判断

实施后只给一个稳定门禁结果入口；每行可展开原始日志。G09 作为正式必需行参与整体判定。该行链接唯一的设计 / 实现对照报告，显示人工决定与机器核对结果，不额外输出多套视觉审核页。其余八类通过而 G09 待审或失败时，受影响工作项仍未完成。

结果字段必须记录 / 校验
运行与来源run_id、工作项、场景 / 正反分支、L1 / L2 / L3、触发事件、开始 / 结束时间；候选与基准身份。
预期与实际预期规则 ID / 阶段 / 效果、实际规则和定位、真实命令 / 退出码 / 断言、文件或数据库前后状态；计数与必要用例列表一致。
时效与归属相关源码、规范、设计、工具与测试输入指纹；必要运行记录绑定包 SHA / 签名、Core / 资源与环境。执行前后比较输入；变更期间产生的结果不签发有效通过。
证据和审核原始日志及产物路径 / hash；实际报告身份与审核结论。Hash 只能发现漂移，不能证明业务语义、作者独立或结果真实，仍需外部观察和必要审阅。
视觉人工决定review_decision=approved / rejected / pending、授权审阅者、确认来源 / 时间、报告内容身份、设计与候选身份、明确页面 / 状态范围。只有当前报告完整可比、无未解决差异且明确获批，G09 才 passed；设计源批准不等于本次客户端对照获批。
状态passed 实际符合预期；failed 实际不符 / 内部故障；blocked 外部条件缺失；not_run 未执行。过期另设失效原因，不能继续作有效 passed 使用。

门禁可启用：必须全部满足

  • 所有必选正例符合各自预期；合法修改无误拦。
  • 普通违规按预期规则拒绝；变异 / 故障按约定被外部验证识别，不接受“碰巧失败”。
  • 拒绝、派发、时效三类关键变异都被识别。
  • 适用 L1 / L2 / L3 全部执行；真实 hooks 与全局配置共存验证通过。
  • 无必选 skip、无缺失结果；独立审阅通过。汇总与视觉判定器用隔离样本验规则，真实产品视觉批准和四游戏不是此处的前置。

产品可准出：另行判断

  • 对应工作项功能、异常 / 恢复完成；适用页面的 G09 当前明确通过。
  • 同一最终签名包的窗口、权限与资源行为通过。
  • SR、MO、Never7、樱之诗逐款完成约定回归。
  • 真实翻译服务、分词 / 注音 / 词典按适用范围验证；缺凭据如实 blocked。
  • 门禁自测通过不能替代上述产品结果；手工门禁与自动门禁具有相同准出效力。
避免重复，也避免漏验。同一有效输入可复用结果；相关源码、合同、设计、检查器、测试或环境改变时，按依赖失效。共享组件、Core、迁移扩大回归；独立说明文档不默认触发全产品。无法归类的生产变更先按保守范围处理，不能默认为无影响。候选最终包身份变化时，包级验收必须重新核对。
