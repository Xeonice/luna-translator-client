## 保留、替换与新增

- 保留 `hook-contracts` 的版本化 JSONL、完整流身份与 64 位数值字符串；保留 `hook-client` 的目标身份重验、会话 generation、宿主管理及 Tauri / React 现有入口。
- 替换 `lunahook-host` 中原版 ABI、DLL 名、十回调注册、旧 `dllinject` 参数、成功退出码 `1` 和 x64 单一编译限制。新注入器退出码 `0` 只表示加载确认，仍要等连接及正文事件。
- 新增 Core 专用资源锁、Windows x86 / x64 两套 broker 和独立运行时目录；包内固定 Core commit、ABI、架构及逐文件 hash，不与旧运行时混装。
- 原文事件、供阅读的文本单元与翻译任务分别建模。Hook 流保留 PID / 地址 / 两个上下文完整身份；不按游戏名、固定地址、流序号或 Hook 名硬编码正文选择，不把一次回调假定为一页。
- 翻译、配置、历史、凭据与未来 Web API 置于 Rust 应用层。Tauri 命令、后续 CLI / HTTP / WebSocket 适配器复用同一应用用例，不把 DLL 路径、FFI 或直接注入暴露给页面。
- macOS 原生客户端通过同 bottle 的 Windows broker 接收 PE 回调；这不提供原生 macOS 游戏取文。后者继续作为独立平台后端任务。

回调仅复制借用数据并快速入队；不能同步翻译、更新 GUI、写数据库或反调 Host。Core 没有可确认的 `Stop / Join`，存活 Host 不执行 `FreeLibrary`，以自有 broker 进程退出回收。资源加载 / 注入 / 连接 / 候选 / 正文状态分开显示。

## M1 必须解决的接入细节

1. 在 M1-01 先新增 `hook-api-v2.md`、保留 v1 文档并冻结 JSONL v2 的字段、错误码、Ready 身份和旧版本拒绝策略，再实现 broker / 客户端两端；M1-03 的 Ready 与 M1-06 的协议实现均遵守这一已冻结基线。使用 `Luna_GetAbiVersion() == 1` 与新七回调签名；去掉旧 embed / i18n / emu 回调。ThreadParam 按值传递，size 32 / align 8 / offset 0、8、16、24，双架构调用约定与字符串借用期均需实际验证。
2. 首版选择 x86 game → x86 broker / Host / Hook / injector、x64 同理。这是已验证边界上的工程选择，不宣称 Core 技术上绝对禁止 Host 跨位数。只支持可核验的 I386 / AMD64 目标，不默默回落。
3. 重新审查依赖旧注入器补丁的游戏禁用规则；不能把旧 `WinVerifyTrust` patch 的原因永久套在新 LoadLibrary 注入器上。继续防止同一目标被多会话 / 旧 Luna 同时占有。
4. Ready 事件带实际 broker 架构与 Core 锁信息；目标身份包含 PID、完整路径、创建时间和架构。每次 attach 重验；进程重启后不能复用旧 stream / translation generation。
5. 控制响应保留优先通道或容量，正文洪流不能吞掉取消 / shutdown。stdout 只承载 JSONL，stderr 独立排空；丢数据通过持久 `integrity_lost` 状态呈现，不能静默“完整”。
6. M1-08 的最小追溯身份是会话实例与 `event_seq`，保留原始增量并忠实显示；不在该阶段推测完整页或阅读单元，复杂 revision / 分段规则留在 M2-03。限额覆盖事件队列、控制队列、流数量、Core 每流历史、客户端缓存及 UI 历史。现每流 100 条 UI 历史和回调队列不能证明总内存有界。
7. 打包从干净暂存目录构建，按 commit + ABI + 架构 + hash 校验整套 Core 资源。签名 / 公证和 Windows 原生安装包分别验证，不能把现有本机未公证 `.app` 称为全平台发布完成。

## M2 的产品验收与设计复用

- 原文先出现，译文随后进入当前阅读单元与历史；翻译关闭、输入暂停、窗口隐藏与断开分别建模。网络超时 / 限流不阻塞取文或保存其他配置。
- 翻译结果至少用 session generation、reading-unit ID、text revision、provider / config revision 关联；快速推进、重连、改服务后旧结果不得覆盖当前句。字符增量与跨页不能靠全局去重或简单前缀裁切猜测。
- 首版 HUD 以当前整稿双档为准：舒适560pt、原文18pt/译文24pt；紧凑500pt、原文16pt/译文22pt；控制行32pt。注音、长文与大字号按当前状态独立检查，不固定旧132pt高度。保留SCR-01追溯和SCR-15单层设置导航，不增加服务专用第二侧栏。
- SCR-04 接入、SCR-05 选流、SCR-08 历史、SCR-15 服务配置构成主旅程；22 屏不是主窗口里 22 个常驻侧栏入口。未完成屏不得用静态演示冒充真实能力。
- 首版以当前整稿、style-guide及材质案例为视觉依据，50张当前截图的确认范围分别记录；旧 `aligned-v1`、`ocr-selection-v2`、`ocr-source-v1`、`compat-x86-v1` 保留各自历史确认状态，不自动成为本轮批准基线。高还原度使用Playwright候选/基准/差异图；原生焦点、置顶、多屏、快捷键、穿透另外实测，不能直接覆盖已确认图。
- API 密钥使用系统凭据存储的引用，日志默认不包含密钥、原文、个人路径；需要共享的实机证据单独脱敏。历史不与候选缓存混为一体；保存失败保留草稿和恢复入口。

## M2-L：先设计，再交付日语阅读和按需解释

本次是规划细化，具体任务为 `M2-L01` 至 `M2-L14`，回归为 `CR-12-*` 与 `CR-13-*`。翻译、学习和资源管理均属于 Rust 应用层及原生客户端，不增加 LunaHook Core 职责，也不恢复原版完整客户端。详见 [架构契约与官方调研](../architecture/japanese-study-and-llm.md) 和 [待评审交互稿](../design/first-product-v1/index.html)。

| 顺序 | 任务 | 实施边界与验收 |
|---|---|---|
| 先评审 | M2-L01 | 展示关闭分词、仅假名、词性色彩、词卡、按需本句解释、AI 请求等待 / 失败 / 不确定与网络离线状态；基础词法和查词按随包内置设计。词性色彩只是 POS，不表示完整文法已分析。先确认可见效果，再开始生产实施 |
| 本地词法 | M2-L02～04 | 规划 MeCab / 基础 UniDic 随应用包内置，首次启动无网络即可分词；另选具有随包再分发条件的基础释义资源，区分形态词典与释义词典。分别固定来源、版本、hash、平台和许可；原生受管 worker 不经 CrossOver broker 或网络。token 绑定原文 hash / text revision / 分词器及词典版本；不可变 `source_text` 不取自 ruby DOM，token 加 gaps 逐字还原原文、空白和标点；未知词明确，UTF-8 byte span 到 WebView UTF-16 索引显式转换 |
| 阅读与查词 | M2-L05～07 | ruby、POS 开关、词卡、随包基础释义和历史版本。读音与原型分开；读音不能可靠逐字映射时按词显示；关闭注音不清原文。点击先显示本地词法及内置基础词典释义，日常无需安装资源；可选扩展独立配置，悬停不自动请求云解释 |
| 服务与请求 | M2-L08～10 | `TranslationProvider` / `ExplainProvider` 分开能力、配置与任务，可同端点不同模型。传统、通用 LLM、本地 / 远程运行器按协议适配；上下文与术语限范围、可查看且版本化；流式中断 / 拒绝 / 截断、取消与缓存独立处理 |
| 按需文法 | M2-L11～12 | 由显式“本词 / 本句解释”触发，文法项引用本地 token / span；允许跨 token 结构、备选与不确定。省略成分是推测，不高亮不存在的文字；最终 schema / 引用校验后才发布结构化高亮。格式合法不证明语义正确 |
| 隐私与发布 | M2-L13～14 | 云翻译 / 解释分别启用，词法不上传；明确 endpoint / 发送范围，密钥不出日志，队列 / 重试 / 输出 / 预算有界。最终安装包重新验证四游戏、真实词法 / 服务、原生交互和失败降级 |

基础语言能力按内置交付规划，当前尚未集成生产资源：正式包携带 MeCab、基础 UniDic 和单独的基础查词释义，首启离线即可使用，不把下载、手选路径或安装辞书作为日常流程。M2-L02 先完成释义来源的再分发许可与覆盖选型；形态词典有词元 / 读音不代表有词义。内置资源 hash / 平台 / 版本与许可证完整性属于构建发布门禁，缺失或不匹配的包不能发布，不为它新增常态缺词典或修复下载界面。基础辞书随应用新版本整套升级。用户可选扩展词典，原 PRD 自定义资源扩展继续留在 M3，基础分词和查词不依赖它。

页面归属沿用 22 屏：`SCR-01` HUD 原文阅读；`SCR-09` 词卡 / 词典及本句解释；`SCR-12` 通用设置展开阅读开关、内置资源版本和可选扩展；`SCR-15` 翻译 / 解释服务配置；`SCR-18` 假名与颜色等外观；`SCR-08` 历史目标句。`SCR-17` 仍是语音设置，不拿来承载分词，不增加第 23 个常驻导航。

原文先显示，再异步词法 / 翻译；AI 解释默认按需。词法和解释分别失败时，原文与其他可用能力继续工作。任务绑定 session / stream / reading unit / text revision / provider 配置与 prompt / 术语版本，切句、切流、切游戏、切模型后迟到结果不得覆盖新句；用户已打开的解释固定到明确的历史目标句。缓存同时包含文本和上下文 hash、模型、语言、模板、术语与词典版本，不能仅按原文字符串复用。

兼容接口不等于相同能力：schema、流式、usage、模型枚举、取消和参数均按具体 endpoint / model 声明及测试；无结构化能力时可清楚降级为纯文本解释，不绘制“已验证引用”高亮。首次门禁至少覆盖两种不同协议的实际适配器和一本地运行器，不以某个供应商硬编码默认，也不默认分发模型权重。翻译专项模型的 prompt / 能力 / 权重许可分别记录，不能假定它也能做文法。

台词、词典和导入术语均按不可信语言资料封装，不赋予模型 Shell、文件、网络跳转等执行工具。并发、重试、输出、缓存及预算有界；usage 不可得时显示未知，不捏造费用；取消不承诺免计费。不得悄悄从本地或关闭的云解释回退到另一个云端。原始请求 / 台词仅在授权的本地证据中保留，默认诊断继续脱敏。

M2-L 中原 P1 功能只是提前选择一个日语子集交付，并不改变优先级或删除完整验收。`CR-11-REQ-001` 至 `CR-11-REQ-056` 原行保持不变，仍由 M3 逐项证明；`requirements.csv` 不据此标记完成。静态设计与可点击演示只说明呈现意图，不能证明生产资源已随包集成、分词准确、模型质量或四游戏实机表现。

## 重建后的回归与发布门禁

使用新的 [CR 回归矩阵](client-regression.csv)，按最终包 hash、Core commit / ABI、架构、CrossOver / bottle、游戏身份和测试时间绑定证据。矩阵中的未执行项保持未执行；本计划不写“已通过”。

- M1：先 ABI / 资源 / 状态机 / 协议有针对性的检查，再验证同一 release 包的安装、选目标、自动接入、选流、实时原文、历史、断开 / 重连及退出。受控 GDI 样本必须经过 Rust 七回调及 JSONL，不能以 C++ 探针替代。
- 四游戏：SR、MO、Never 7、サクラノ詩 10th 逐个完成后再换下一个，每款至少 5 个不同字幕变化状态，核对画面、候选、原文与历史。SR 的中文文本按实际版本验收，不强称日文；Never 7 检查增量与跨页；MO 检查跨页；サクラノ詩检查同名候选流质量差异。Ever17 不在本轮范围。
- M2：在上述原文链路上加真实服务请求与可见译文，验证旧结果隔离、服务超时 / 关闭、配置重启、历史对应和 HUD 原生行为；GUI 产品记录不能被无界面日志替代。
- 稳定性：每款首轮 100 次字幕变化或 30 分钟（记录实际达到的样本，不宣称长期稳定），再覆盖快进、读档、游戏退出重开及 broker 异常。存在的 MO 图形 / 内存异常单列保留，取文成功不等于该异常已修复。
- M2-L：M2 基线后，在同一最终包执行 8 条 `CR-12-*` 和 10 条 `CR-13-*`。内置 MeCab / 基础 UniDic / 基础释义的无网络首启、实际本地词法、两种协议适配器及一本地运行器、按需解释与四游戏最终包各自留证。SR 当前为中文，不伪称日文证据；日文手动样本作为独立输入验收。MO 旧异常和 Steam 环境阻塞继续独立记录。
- M3：按原 REQ / SCR 补足 P0 后再声明完整 P0；P1 / P2 和 Windows 原生 / macOS 原生游戏分别维护支持清单及证据。缺游戏、登录、权限或服务时记录受阻，不用假数据补通过。

每次变更只运行受影响的有意义检查；新 Core 资源、协议、会话或构建变更必须补跨架构与最终包回归。提交 / 推送不在本轮规划授权内，后续仅在用户明确要求时执行；提交前检查 debugger、秘密及意外内容。
真实游戏台词、截图、崩溃采样及个人运行路径保存在本地证据目录，发布摘要仅保留脱敏统计与包身份。保留 LunaHook 原 LICENSE、作者声明及第三方许可证；产品包附来源与修改说明。
