# 设计对齐与准出

视觉是九类门禁中的独立G09。依据[当前设计](../design/first-product-v1/README.md)和[已批准门禁设计](gate-validation-design.html)，只维护[一份设计/实现统一报告](../../reports/visual-comparison/index.html)，不再要求用户反复审核多套叠图、像素百分比和参照审批页。

## 捕获和报告

按实际源码依赖选择页面、状态与真实client尺寸，Playwright捕获真实组件；原生材质、窗口和系统行为使用正式包画面。同尺寸、主题、数据和状态并排，注明源/包/环境、差异、修复状态与待确认项。主窗/历史1040×720、设置1000×720与760×560窄窗沿用各自批准范围。原型或旧截图不能冒充实现。未知影响保守处理，缺适用状态不能按一张正常图关闭整页。

## 手工决定，程序阻断

机器核对报告/PNG可读性、身份与覆盖；用户或其指定审阅人明确确认视觉。审核记录绑定报告与manifest、相关源码/包、页面状态、视口、审阅人、时间及真实确认来源。实现者、模型或报告生成器不得自行写approved。

| 情况 | G09 |
|---|---|
| 未执行/未生成 | not_run |
| 缺图、不可比、损坏或被拒绝 | failed |
| 报告完整待确认 | blocked |
| 当前范围完整可比、无未解决差异且明确确认 | passed |
| 相关实现/设计/截图变化 | 旧确认失效，保持未完成 |

未通过时拒绝受影响页面/工作项完成、阶段准出和发布；允许修复、独立工作与安装待验候选。等待人工时Stop可结束但保持incomplete，不无限重拍。

## 保留和迁移

guided/R79、C35、通用设置及容器尺寸的既有源版批准继续有效，不改批准图。旧像素检查及失败作为历史原件保留；本轮不靠重拍或降低阈值修改旧结论，而是显式采用新的人工视觉裁决流程。新候选不自动继承旧S5或Source62产品接受。

报告生成工具为scripts/quality/visual_review.py，只生成页面不生成批准。G09有效性由GV03、GV31、GV32验证，测试fixture只能验证判定器，不能成为产品视觉批准。
