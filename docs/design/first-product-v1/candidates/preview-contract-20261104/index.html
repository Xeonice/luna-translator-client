本次需确认的五处补充

  1. 把演示标记放在评审工具区。 产品内使用“实时预览”“已暂停”“画面已过期”等真实状态；保留旧帧时明确标“最后画面”，不出现离线回放标签。
  2. 身份措辞跟随可得事实。 仅选择目标不等于已核验；游戏资料来源与候选发现分开。只有独立完整核验记录成立，才显示“身份已核对”；缺少的 Native 字段保持“未提供”。
  3. 补齐安全边界。 固定346px卡高；纵排图限宽280px并居中，避免中间宽度挤压说明。容器内容宽达到520px才横排（带边框的外宽522px）。200%详情约束在视口内，只有正文滚动。
  4. 补齐旧帧生命周期。 暂停与过期保留最后成功画面及原采集时间；权限拒绝、撤销、关闭及身份变化清除可显示帧，不把旧图标为实时。“继续”只进入等待恢复，不抹去已知的最近成功历史时间；首次启动尚无历史时仍显示未提供。没有新帧就不更新时间。不可用且无有效复用证明时也不显示旧图；有有效复用证明的暂态用“画面已过期”表达。
  5. 详情展示真正可得的事实。 采集投影权限与最近能力检查分行显示，说明来源与时间；完整路径、核验摘要、Native API、阶段/操作等只展示已有事实。样例未提供的字段不填固定假值。

此稿仅提出上述呈现与状态判定补充，不改变 Hook、采集器、订阅、权限权威或游戏窗口。采集恢复、系统授权与同包游戏回归仍需真实客户端验证。
