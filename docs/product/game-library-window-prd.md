# 游戏入库、运行目标选择与窗口关联

本页定义当前游戏库与目标关联的用户流程。窗口核对后一次“关联并接入”确认即启动Hook，无需另点连接；真实预览、接入、收到文本与选正文分别呈现。继承REQ-002、004、037、043和SCR-02、03、04，原始快照与历史执行原件保留。现有源码、尚待完成的页面任务和本次工作状态分别以[客户端技术设计](../architecture/reading-window-session-technical-design.md)、[整页交付计划](../development/current-client-alignment-plan.md)和[当前阶段](../development/current-phase.json)为准；本页不声明产品回归通过。

## 原版行为与本次选择

| 原版操作 | 源码证据 | 本产品的选择 |
| --- | --- | --- |
| 游戏管理中添加文件或文件夹 | `gui/gamemanager/common.py` 的 `addgamesingle` / `addgamebatch` | 添加记录与启动、接入分开；保存后可选择下一步 |

## 首次使用与已有记录

首次启动显示空游戏库，提供“添加游戏…”和“连接运行中的游戏…”。恢复记录才显示已保存游戏。四款此前采集的游戏是评审用恢复样本，不能伪装成所有新用户都已安装的游戏。

### 从本地文件加入

选择或拖入程序 → 核对游戏名、运行环境、Bottle与实际取文程序 → 保存入库 → 从页头“连接运行中的游戏…”选择已运行目标 → 同面板核对并一次“关联并接入” → 检查接入 → 显式选择正文 → 阅读。首版客户端不启动游戏；保存的历史启动配置不因此产生用户启动入口。

正式客户端应从原生文件选择器取得完整路径，自动填充可识别的名称、运行环境、容器与架构；仅在缺失或有歧义时要求补充核对。参数和工作目录保留为可选项，不要求用户手动配置DLL。

浏览器设计稿只能拿到文件名时，完整路径保持待核对，不把 `fakepath` 当作已识别路径。目录或快捷方式存在多个候选时先选择实际 EXE。尚未解析的快捷方式不能冒充已找到目标。未知程序没有此前样本时，不套用其他游戏的台词或“接入成功”状态。

### 从已运行的游戏加入

从游戏库页头“连接运行中的游戏…”打开不携带选中卡片gameId的全局目标面板；按实际candidate完整身份匹配已入库目标，卡片A被选中不能覆盖运行目标B归属；当前会话明确重连等scoped入口保留真实用户归属意图 → 在面板内选择运行窗口或进程 → 同面板核对完整身份及真实预览，必要时在此完成系统单窗口确认 → 匹配已有库记录或核对新记录 → 仅一次确认“关联并接入” → 查看真实接入阶段 → 等待并比较候选文本 → 勾选正文来源与保存意图 → 显式“开始阅读”。

选择只是核对候选，取消不改变当前连接。窗口列表和“点击选择窗口”得到的Windows取文目标，与macOS系统单窗口共享确认分别说明；不能因选到取文目标就声称画面已核验。ANSI自动配对不可用时，在当前核对面板明确提供“选择对应的游戏窗口…”，系统确认后的真实预览留在此处供核对，关联时转交同一正式会话，不要求关联后再选择一次相同窗口。普通刷新、挂载和轮询不自行弹系统选择器。预览拒绝、取消或暂不可用时仍可依据已核对Windows身份明确继续Hook，不能把预览成功变成取文前置条件。用户确认后，无须再回到进程列表手动连接。映射不唯一时需要选择实际目标；无法映射或目标退出时可以刷新、重新选择或改用进程列表，不能直接显示关联或接入成功。

这里的“预览”须明确区分目标资料核对与真实窗口图像。运行目标列表、目标核对和当前会话提供同一目标的窗口预览入口；已选有效目标且录屏权限具备时自动展示来自本次实际窗口的连续更新帧，以及窗口名、程序/Bottle、最近采集时间与实时/暂停/失效状态。素材封面和历史截图不能冒充当前帧。不再要求每次点“开启窗口预览”。用户明确选择运行目标后按系统需要申请权限并说明用途；已有权限直接预览，授权返回后自动恢复本次有效目标。拒绝后仍可核对目标和Hook接入。正式关联后预览由会话持有，正文、全部提取、Hook诊断折叠区展开/收起不停止采集。窗口最小化、目标退出、权限拒绝和暂时取不到图像分别显示；旧帧标明时间并停止声称“实时”。完整身份与生命周期规则见[RW-01～06](reading-window-session-prd.md#真实运行窗口预览)。

### 已有会话的窗口关联

当前会话和字幕“更多”提供“选择/更换游戏窗口…”与“解除窗口关联”。选择或点选后都进入同一核对面板，以“关联并接入”确认。操作前后显示当前窗口标题、目标程序及接入阶段。

- 没有活动取文会话时，确认关联立即启动所选目标的Hook接入。
- 已连接同一目标时，复用现有会话、正文选择及历史；更新经核验的窗口关联，不重复注入。判断须核对Bottle、完整路径和本次进程身份，不能只比较PID或标题。
- 选择不同目标时，在确认处明确说明将切换取文对象，得到确认后才结束旧会话并接入新目标；取消保留旧关联和会话。
- 接入失败时保留仍有效的已核验窗口，显示“窗口已关联，取文接入失败”及具体阶段，提供“重试接入”。重试前再次核验目标身份；失败不显示为已收到正文。
- “解除窗口关联”只清窗口关系，保留Hook会话、原句和历史。要停止采集，使用独立的“断开取文”。窗口退出时清除失效关联，保留库记录与专用配置；Hook状态按自身运行结果更新。

窗口关联、Hook连接、收到回调和选择正文分别记录。核对面板根据Rust实际确认的同目标关系显示复用或切换；旧核对结果失效时先重新核对，不能把后来出现的会话当作已同意切换。用户一次确认触发关联与Hook，随后依次表达窗口已关联、自动接入、已连接等待文本、已有候选及正文确认；接入内部的身份/资源核验、启动请求与真实握手分别显示。不能以按钮pending、确认返回、DLL加载或计时器冒充接入完成。接入失败保留目标与具体阶段，可重试；关闭阶段观察面板不解除已经成立的绑定或停止后台接入，也不能使已成功会话永久没有常驻预览。收到当前operation的真实候选事实后，面板进入正文来源选择；不要求已完成的阶段列表继续占据来源面板。接入失败必须有明确“重试接入”操作，单纯“可重试”文字不构成恢复入口；重试先重新核对目标。选择客户端自身不发起接入；解除使用显式按钮。

## 正文来源确认与开始阅读

本节落实已批准完整稿中正文候选、记住选择和开始阅读的交互，细化FP-03/04/05/09/12；它不把当前单流接口当成已经交付，也不改变原GL/RW验收ID。用户在同一连接旅程比较候选，再明确确认阅读：

- 候选展示真实完整样本、Hook与编码；完整最新样本及Hook、Address、Context、Context2按需展开。不能按名称、第一条、固定索引或猜测正文自动选择。
- 勾选只修改本次草稿，可选择一个或多个来源；显示已选数量。展开样本、切换勾选、开关“为这款游戏记住选择”均不立即写入有效选择或开始消费。
- “开始阅读”对当前会话一次提交全部选择；没有选择时禁用。提交失败保留草稿及错误，不能部分采用或只保存最后一项。“稍后选择”保留已连接会话，不提交草稿、不自动选择第一条。
- “记住选择”与临时选择分开。已归属游戏时，明确保存所选来源的匹配说明；只做临时选择不覆盖此前保存的说明。仅本次连接且没有游戏归属时禁用保存并说明原因，不能悄悄转成保存或静默丢弃保存意图。
- 同一会话重开候选时显示实际已采用集合。后续会话可展示此前明确保存的来源供核对；当前来源缺少可靠可移植身份、未匹配或存在歧义时，明确“需要重新核对”，不靠Hook名、旧sourceId、裸PID或受ASLR影响的绝对地址自动勾选。保存成功不保证跨版本、跨启动一定能自动匹配，且任何预填都仍须“开始阅读”确认。
- 集合确认成功后先显示字幕浮窗并确认可见，再隐藏主窗口。选择已保存而窗口操作失败时，明确区分两项结果并提供重试窗口显示；重试不重复保存、不重新注入，也不能用旧会话请求影响新会话窗口。

两条来源交替输出时保留各自来源和版本，不把不同来源的原文硬拼成同一个阅读单元。历史原文、译文和来源不因新选择或保存策略而被改写。单个来源的旧入口继续兼容，但必须遵守同一次原子选择与版本校验规则。

## 封面与连接入口

- 首版只连接已运行游戏。删除游戏详情的“运行并连接…”“关联并接入…”“连接已运行的游戏…”三个冗余入口，卡片单击/双击/更多均不启动游戏。页头统一连接入口保留，当前会话/HUD的更换窗口、解除关联与断开属于恢复操作。
- REQ-038封面优先读取与已核对游戏对应的本机Steam/游戏资源；读取静态封面不依赖录屏权限，授权本身不生成图片。加载失败明确占位，不借其他游戏封面。
- 用户已明确选择“自动读取本机封面，无图时自动保存首张游戏画面”。仅正式关联有效目标且已有录屏权限、当前游戏无封面时，首张有效帧可写托管资产并绑定游戏。候选浏览/取消、失效身份、旧generation、其他窗口、无权限帧均不保存；不持续录制、不覆盖已有封面。
- 封面来源、本机资源失效、保存失败及重启恢复有可见状态；静态封面不标实时。托管资产写入/安全显示链须实际验证，不只检查cover字段。移出游戏库不删除用户游戏文件。

## 身份与保存规则

| 对象 | 保存或校验的内容 |
| --- | --- |
| 游戏记录 | 稳定记录 ID、名称、运行环境、Bottle 引用、启动路径、实际目标路径、架构、参数、工作目录 |
| 重复判定 | 按运行环境 + Bottle + 规范化目标路径匹配；同名 EXE、相同裸 PID 不足以判为同一游戏 |
| 运行关联 | macOS 窗口身份/宿主进程与 Bottle 内 Windows 目标分别保存，并绑定本次运行身份 |
| 重启或目标退出 | 重新发现并核对；不把上次 PID/HWND 当成持久游戏身份直接复用 |
| 编辑/移出游戏库 | 修改元数据前显示受影响目标；移出库保留历史，不删除用户游戏文件 |

修改目标身份后，旧的文本流选择和运行窗口关联不能冒充新目标已验证。不同 Bottle 的相同路径允许作为独立记录，专用设置不自动合并。

活动会话保留连接时的目标和原句语言快照。即使库记录被编辑或移出，仍按本次HOOK目标推进与翻译；关联到不同目标时在同一核对流程明确确认切换。重新关联活动会话窗口也按该快照核对，不能只凭相同记录ID接受另一个游戏的窗口。

## 交互和验收

统一使用当前中性线性图标、暗色磨砂与轻返回入口。添加和目标核对在附属面板中完成，取消保留游戏进程。按已确认C1使用1040×720主窗口、760×560窄窗及200%内容测试；目标身份、必要系统确认和最终确认操作保持可达。搜索、扫描和其他容器的告警不得挤占当前目标核对的主要层级；实际故障可查且不隐藏，非当前目标的诊断收敛到次级说明。窗口列表与映射结果可读，高级句柄按需展开。

用户选择有效运行目标后，权限已具备即自动预览；缺权限明确申请/系统设置/重新检查，授权后恢复目标。确认关联同时启动Hook并让预览随会话常驻；可暂停/恢复但不提供每次开启的前置步骤。持续预览不录制、不连续保存、不含音频，不启动OCR或上传模型/云端。无封面游戏在正式关联、身份有效、已授权且首帧有效后，允许保存一张静态封面；该用途与持续预览分离。OCR仍按原路线另行设计和验证。

绑定旅程以“库页入口→候选核对与必要系统确认→一次关联→真实接入阶段→候选草稿→开始阅读→会话继续持有预览”为整体验收单位。正常流程、同目标复用、不同目标切换、取消、失败重试、临时/记住、旧操作迟到分别验证；恢复入口可用不能替代正常流程对齐。当前实现仍有两套选窗分离、同目标误标切换、阶段呈现及单流即提交等差距，详见[当前交付计划](../development/current-client-alignment-plan.md)。完成这些目标前保持未完成。

当前产品评审以[完整设计入口](../design/first-product-v1/README.md)指向的已批准组合与独立状态参照为准。已有源码及包身份见[客户端运行说明](../development/desktop-client.md)；历史Reader切片只按各自原件追溯，不作为当前流程或同包验收通过。设计演示、原生切片和最终产品证据分别记录。

[产品验收清单](game-library-window-acceptance.csv)全部为 `NOT_RUN`。原型的交互截图与检查另记在设计证据中；不得代替真实文件解析、原生窗口选择、CrossOver 映射或 HOOK 回归。

本轮真实窗口预览、字幕与会话新增验收单列于[RW矩阵](reading-window-session-acceptance.csv)，全部 `not_run`。原GL身份和NOT_RUN计划状态保持；本轮受影响预期按用户明确覆盖更新，旧定义字节与既有运行记录保留；尚未纳入执行器的RW项不能因相近的GL/FP用例通过而视为已覆盖。
