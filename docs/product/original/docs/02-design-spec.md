# LunaTranslator macOS 客户端设计规格

本设计覆盖 LunaTranslator 的完整桌面翻译、游戏接入与辅助阅读工作流，需求范围见 [产品需求](01-prd.md)。客户端以 Rust 核心和独立 hookbridge 为边界，界面遵循 macOS 窗口、侧栏、工具栏、列表和详情视图习惯。常驻翻译浮窗支持pin置顶和全局快捷键显隐；“无游戏实时OCR翻译”（US-10）是独立完整流程：全局命令唤起屏幕选区层→拖框松手即开始→持续捕获识别→浮窗原文/实时译文；应用窗口绑定为次级入口，不要求游戏或HOOK。Mac游戏接入区分execution_environment=`native`与`compat_windows`；后者包含CrossOver/Wine等环境中的Windows游戏。具体游戏、架构、引擎、文本提取及内嵌能力由对应环境的兼容性结果决定，不把Windows游戏目标显示成原生Mac进程，也不把OCR画面识别当成直接游戏取文。

以下尺寸、布局、文案和状态属于本产品的设计决策，供可编辑设计预览、实现和验收共用；Apple HIG 为平台原则依据。用户于2026-10-13确认[aligned-v1全22页](../design/README.md)设计，现有60张截图保留为PRD 1.1的视觉基线。本规范同步当前PRD 1.2；本轮6张ocr-selection-v2选区/任务页视觉有单独用户确认与hash，上轮15张ocr-source-v1仍not_reviewed。2026-10-16新增SCR-03/04/22的`compat-x86-v1` 8张兼容样张为visual_checked / not_reviewed；未捕获状态另验，不继承或扩张已确认范围。需求优先级决定实现依赖顺序，不删除完整产品能力。

新客户端、原生/兼容环境接入、bridge及下面的运行时交互均为待实现规格。技术计划采用Tauri 2＋React/TypeScript＋Vite共享UI与Rust核心，详见[架构选型](03-client-architecture.md)。Windows与macOS共用22页、HUD和选区的源码、组件、主题tokens与command/projection绑定；必要差异由平台系统adapter、语义样式和键位映射表达，不另维护完整原生页面。当前原生预览仍是设计载体，不携其本地假状态进入生产；选定路线不等于GU通过，Mac截图accepted不扩张到Tauri实际WebView或Windows视觉/辅助技术。本次按用户选定的x86兼容路线新增CrossOver/Wine可编辑变体与8张样张；旧native/OCR稿与批准图片hash保持原确认范围。新增稿固定memo01为明确设计示例，各能力均为未验证。画面、局部样张交互和视觉复查不证明客户端功能或真实游戏兼容性已完成。

本文的原生List/Table、Form、switch、Menu、SF Symbols、`.hudWindow`与系统font/color等术语描述已确认Mac基线的布局、交互和视觉语义，并不要求生产使用SwiftUI页面。生产页以同一套共享HTML组件实现这些语义；真实OS菜单、窗口材质、焦点及系统偏好由必要的薄adapter提供，系统字体与语义颜色映射参与共享主题。CSS圆点、blur或模拟开关不能自证等同原生行为或系统材质；需在WKWebView与WebView2中分别验证实际合成、键盘、读屏、文本选择和200%缩放，任何新稿的视觉确认按实际反馈另记。

## 1 平台设计原则

主窗口采用可调整宽度的分栏，保留菜单栏命令、键盘操作、多窗口和窗口位置恢复。macOS HIG 建议利用桌面空间、减少不必要的模态层级，并支持窗口调整与键盘操作。[Designing for macOS](https://developer.apple.com/design/human-interface-guidelines/designing-for-macos/)

侧栏只承担导航，最多两层；工具栏只保留当前内容的常用命令，所有工具栏命令都有菜单栏入口。核心工作流采用原生List/Table与split详情，操作以安静的单色图标和原生菜单为主。设置按用户参考采用柔灰侧栏、24pt彩色语义图标tile和中性灰选择态，颜色表达设置类别，不作为整行背景或成功证明；焦点与原生开关仍使用系统强调色。[Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars/)允许有清晰含义的有限图标颜色，具体tile、选择态和尺寸是用户确认的产品设计，不是HIG强制数值。

材质按用途区分：历史、表格和表单以稳定内容背景承载；SCR-01使用标准半透明`.hudWindow`阅读材质。标准材质与Liquid Glass不同，浮窗正文不施加Liquid Glass，图标也无常驻玻璃圈、描边和阴影外壳。HIG [Materials](https://developer.apple.com/design/human-interface-guidelines/materials/)的“Don’t use Liquid Glass in the content layer.”不禁止标准内容材质；不把“减少透明度”的可访问性回退误写成日常默认实色。

界面优先使用系统字体与颜色。macOS 不支持 Dynamic Type，本产品提供自己的界面和阅读字号缩放；CJK 内容通过系统语言字体回退渲染。[Typography](https://developer.apple.com/design/human-interface-guidelines/typography/)、[Color](https://developer.apple.com/design/human-interface-guidelines/color/)

状态同时用文字、图标和颜色表达。所有主要流程提供键盘及 VoiceOver 路径，响应增加对比度、减少透明度和减少动态效果；不会自动消失的错误说明方便辅助技术完整读取。[Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility/)

## 2 信息架构和窗口

### 2.1 主窗口导航

下面分组说明功能归属，不要求22个SCR同时常驻主侧栏；评审应用的“页面”菜单用于逐页检查，不是生产客户端的常驻功能清单。浮窗、连接sheet、选区层和瞬时查词由当前任务入口打开。正式导航的作用域和运行会话状态由Rust投影提供，视觉沿用已确认的侧栏语法。

| 侧栏分组 | 导航项 | 内容组织 |
| --- | --- | --- |
| 游戏 | 游戏库、当前会话 | 游戏列表 → 游戏详情或实时会话；接入游戏只在用户执行连接命令时启动 |
| 文本 | 文本与文件、历史记录 | 文件任务或文本列表 → 内容编辑、结果与详情 |
| 阅读 | 查词、Anki 卡片、备忘录 | 条目列表 → 词条、卡片或笔记 |
| 工具 | 设置、接入兼容性、诊断 | 设置分类列表 → 表单；兼容性与诊断采用表格详情 |

已连接会话显示在侧栏“当前会话”下，名称与状态文字可读；独立OCR会话同属当前会话，以“屏幕区域”或用户选定的应用/窗口名称显示，不需要挂在游戏记录下。关闭主窗口不等于断开会话、停止OCR或退出程序。菜单栏常驻图标提供“打开主窗口”“显示/隐藏翻译浮窗”“框选实时OCR区域…”“恢复浮窗交互”“暂停/继续自动输入”和“退出”；OCR运行时还提供“调整范围…”与“停止实时OCR”。从 Dock 再次打开恢复主窗口，不重复创建会话。

完整套预览参考尺寸为1000 × 720pt，常规最小测试尺寸为900 × 600pt；具体布局按信息密度调整，浮窗和屏幕选区使用自己的尺寸。默认侧栏190–220pt、内容列表按任务取约240–300pt，详情占剩余宽度，分栏可调。窄窗首先收起可选检查器，其次将列表/详情改为单列返回路径；允许显示/隐藏侧栏，不能为守住三列而缩小正文或省略功能。位置、栏宽、排序和最后选中项按配置保存；外接显示器断开后将窗口移回可见范围。

### 2.2 窗口类型

| 类型 | 用途 | 默认行为 |
| --- | --- | --- |
| 主窗口 | 游戏库、会话、历史、阅读资料 | 标准标题栏、红黄绿窗口按钮、resize、全屏、菜单栏命令 |
| 设置窗口 | SCR-12 至 SCR-21 | 独立标准窗口，全套参考1000 × 720pt、最小900 × 600pt；柔灰侧栏与Form分组；与会话同时使用，⌘,打开 |
| 连接 sheet | SCR-04 | 附着游戏库或发起连接的主窗口；参考840×660pt，可以取消，连接完成后进入文本选择；不阻塞其他独立窗口 |
| 翻译浮窗 | SCR-01 | 应用运行期间可常驻，首次提供可见等待输入；默认约500 × 132pt、最小宽360pt；固定32pt操作行在正文滚动区外；标准半透明hudWindow，可移动/调宽、更多菜单pin置顶、全局快捷键显隐，不夺目标应用焦点 |
| 查词窗口 | SCR-09 | 短词义使用 popover，完整词典使用普通窗口；可固定以保留结果 |
| 屏幕选区层 | SCR-06 | 全局快捷键/菜单从其他应用直接唤起并覆盖目标屏幕；冻结画面定位、十字准星拖框，松手即开始；调区Return应用，Esc取消，结束恢复原前台焦点 |
| 导入向导 sheet | SCR-20 | 预览、映射、冲突处理、执行、结果；退出不损坏当前配置 |

翻译浮窗是持续展示游戏及其他应用原文/译文的专项窗口，不能机械套用普通辅助 panel 在应用失焦时隐藏的行为。pin置顶时切换到游戏、视频或浏览器仍保持浮窗可见；显示/隐藏仅影响窗口呈现。普通检查器和瞬时 popover 仍按当前任务管理，避免长期盖住目标应用。[Panels](https://developer.apple.com/design/human-interface-guidelines/panels/)

### 2.3 菜单和快捷键

菜单包含“LunaTranslator”“文件”“编辑”“游戏”“输入”“显示”“窗口”“帮助”。⌘, 为设置、⌘F 为当前视图搜索、⌘N 为当前上下文新建、⌘W 为关闭当前窗口；编辑菜单使用系统复制、粘贴、全选、撤销习惯。新增游戏与新增文本遵循当前导航上下文，菜单名称明确，避免一个快捷键执行难以判断的动作。

“输入”菜单提供“框选实时OCR区域…”直接唤起目标屏幕临时覆盖层，普通应用前台、无游戏和主窗口关闭时也可执行；浮窗更多菜单与菜单栏常驻图标提供同名入口。“查看实时OCR任务”进入SCR-06工作页查看/配置/恢复；次级“绑定应用窗口…”提供跟随窗口捕获。“一次OCR…”单独列出，不能与启动持续识别共用模糊名称。OCR运行时“调整范围…”与“停止实时OCR”在相同菜单分组中可发现，运行控制不要求打开引擎设置。

全局热键由用户在SCR-18配置；“框选实时OCR区域…”设计建议⌥⌘O，直接从其他应用进入全屏拖框，“显示/隐藏翻译浮窗”建议⌥⌘H，两者独立可改。选择过程临时接收拖框/取消及调区确认，结束恢复原前台焦点。浮窗显隐为全局作用域，游戏或其他应用前台时仍可执行，不激活主窗口或夺目标焦点；它不改变OCR/HOOK采集、翻译开关或pin选择。“暂停/继续自动输入”和“恢复浮窗交互”是独立命令。初始不抢占游戏常用按键；冲突时显示冲突对象或无法注册原因，实际注册成功才显示已启用。无法注册时，菜单栏仍可框选、显隐或解除穿透。右键便捷动作、拖动排序、悬停查词均有可发现的菜单或按钮等价操作。

### 3.2 字体与阅读

| Token | 字号 / 行高 | 字重 | 使用 |

| type.windowTitle | 17 / 24 pt | Semibold | 标题栏内容标题 |
| type.pageTitle | 23 / 30 pt | Semibold | 设置与详情标题；不重复大号品牌标语 |
| type.section | 13 / 20 pt | Semibold | Form分组、阅读区小标题 |
| type.body | 13 / 20 pt | Regular | 可读正文、表单值、列表名称与重要不可用原因 |
| type.caption | 12 / 18 pt | Regular | 时间、参数说明、来源 |

| type.overlaySource | 16 / 24 pt | Regular | 浮窗原文默认值，可独立调整 |

| type.overlayStatus | 13 / 20 pt | Regular | 暂停等持续状态文字，不靠图标颜色猜测 |

UI 字体使用系统 font API。中文和日文通过系统 locale 与脚本回退；不把 SF 强行指定为所有 CJK 字形，也不把 Apple 系统字体打包分发。当前原生设计预览使用系统字体，生产呈现层沿用系统字体回退链。对话、译文、词典结果不使用 Thin 或 Light；长句自动换行，完整内容可选择复制。日文标点、组合字符、emoji 和中日混排不得在 grapheme 内截断。注音独立占用 ruby 行距，开关注音不会盖住正文。

界面提供 100%、125%、150%、200% 文字缩放，200% 时表单标签和值改为上下排列、列表提高行高；正文阅读和浮窗字号独立配置，浮窗支持 12–48 pt。关键名称和错误在大字模式下换行，地址等技术字段可横向滚动，不整体缩小文字以塞入固定容器。

焦点样张为 accent 2 pt 轮廓，运行时采用平台焦点环。减少动态效果时取消位移、缩放、弹簧和自动闪烁；短静态状态或淡入仍需保留明确反馈。减少透明度时 sidebar、toolbar、popover 和浮窗均有实色替代，不通过手工模糊效果绕过系统设置。

### 3.4 已确认的布局语法

HUD的单一职责是读当前原文与译文，静止时仅保留暂停/继续和更多两个安静入口；更多菜单包含pin置顶、显示控制、“框选实时OCR区域…”及其他命令。OCR运行时在更多中提供“调整范围…”与“停止实时OCR”，不增加常驻捕获控制条。暂停后的“已暂停”13pt文字持续可见，置顶用菜单勾选表示实际窗口状态，不从参考截图的白色图标猜测状态。完整可配置工具栏仍在SCR-18管理，用户可展开/固定其常用命令；两个默认入口不表示删除手动读取、OCR、查词、历史或游戏工具。

设置的单一职责是按类别调整可见配置，采用Form分组、行标签/值/原生开关、辅助说明和必要执行按钮，不把每个字段包装成仪表盘卡片。内容密集时使用展开区、独立编辑sheet或list/detail；连接失败、未验证能力和越界参数说明跟在相关字段旁，13pt可读。正文、日志、预览和数据表不套用HUD半透明样式。

核心窗口使用原生List/Table、split详情和任务相关toolbar；设置类别与同一Form内的服务选择各有自己的状态，不增加服务侧栏。没有统一要求把22页都变成同一个card/dashboard模板。缩小时保留同样功能与菜单入口，改变可见分栏而不删需求。

## 4 通用状态和交互契约

| 状态 | 视觉和操作 |
| --- | --- |
| 空内容 | 一句说明 + 一个直接操作，例如“尚未添加游戏”“添加游戏…”；不显示营销插画 |
| 正在加载 | 固定位置 progress 和任务名；已有内容仍可阅读；可取消的任务提供取消按钮 |
| 成功 | 更新列表或内容 + 可读状态；批量任务给成功/失败数量；不靠短 toast 承载结果 |
| 失败 | 原因、受影响范围、重试/修改设置；原文、上次成功译文和用户编辑保留 |
| 不可用 | 显示当前条件和所需能力，不隐藏该产品功能；可导航到兼容性或替代输入 |
| 未保存编辑 | 离开时明确保存、放弃、取消；自动保存的笔记显示保存状态及可恢复历史 |
| 离线或断连 | 仍可查历史/编辑配置；显示连接中断与上次成功时间；恢复后不重复提交旧卡片或文件任务 |
| 运行中的文本更新 | 用户正在选择文字、查看旧历史或编辑时不抢焦点、不滚走；“回到最新”恢复跟随 |

功能状态采用PRD的两个维度：实现状态为“规划中、开发中、实验性、已验证”；目标适用性为“跨平台核心、需原生适配、需兼容环境验证、平台专用、不支持”。execution_environment另行表达native或compat_windows，与上述状态独立。规划中的功能在设置和能力说明中展示，不在实际会话里呈现成可执行成功操作。具体目标再分别显示启动、helper/bridge就绪、连接、取文及回写结果；“游戏可运行”不是“可HOOK”。

译文按 event/session/source 标识关联，不能因晚到结果覆盖新原文。多翻译器结果各自显示进行中、完成或失败；一个翻译器失败不使其他结果消失。流式结果就地增长、不抖动布局；暂停是停止自动输入，保留手动读取、编辑和已有历史。具体队列和处理语义由 PRD 和技术规格定义，界面只呈现真实状态。

修改全局与游戏配置时固定显示作用域：“全局”“当前游戏”“当前配置”。“跟随默认”表示该项不设生效中的专用值；“继承全局词典”明确表示合并而非覆盖。首次关闭跟随且无自定义备份时复制当前有效值；已有备份时恢复先前自定义值，重新跟随期间的全局更新不覆盖备份。恢复默认能预览将被替换的项。每个设置项显示有效值及来源，避免用户看到一个值却不知由哪层配置决定。

## 5 全部 screen 规格

### SCR-01 翻译浮窗

取得实际说话人姓名时，原文以同一阅读字号显示“姓名：正文”，姓名与本条文本事件绑定；未取得或游戏未显示姓名时仅显示正文，不猜测为某个角色或旁白。姓名按完整文本换行、可选择复制，随正文共同缩放及滚动；固定暂停/更多操作行保持不变。此新增姓名呈现需查看真实共享UI样张，不扩展已有稿件的视觉确认范围。

- 内容：应用首次运行提供可见常驻浮窗，未连接游戏时显示“等待输入”，更多菜单可直接开始实时OCR。默认约500 × 132pt、最小宽360pt；原文16pt、译文22pt、持续状态13pt；标准半透明hudWindow正文，前景不降透明。32pt固定操作行在正文滚动区之外，默认暂停/继续和更多两个入口，16pt Medium单色符号、32 × 32pt矩形命中、8pt间隔；静止无glass圈/描边/阴影外壳，hover为primary12%的radius8局部反馈；自定义暂停按钮press为primary22%，更多Menu保留原生按下反馈。可配置完整工具栏保留手动读取、一次OCR、查词、历史、恢复/开启穿透、朗读及游戏工具，并可添加、排序或固定。Yomitan及辅助动作按宿主/平台能力提供；OCR区域/窗口来源与会话可在更多菜单/历史检查，不加常驻大标题或技术页脚。
- 状态：等待文本、自动输入、已暂停、翻译中、部分服务失败、断连、点击穿透、隐藏原文、隐藏译文、浮窗隐藏、完全透明、固定工具栏、目标应用失焦。OCR识别原文到达即显示，翻译失败给可读原因/重试且原文保留；旧句译文不冒充当前结果。暂停持续显示“已暂停”文字并将动作改为继续；置顶在原生更多菜单勾选，状态不只靠符号颜色。
- 交互：默认不夺取游戏或其他目标应用焦点；用户点击文本明确进入可选择的交互模式。更多菜单“置顶”可pin/取消，常规pin在客户端失焦时保持；可选失焦取消置顶策略另设。“显示/隐藏翻译浮窗”全局快捷键隐藏并恢复同一浮窗与当前内容，不停止采集或翻译；“暂停/继续”才控制自动输入，停止OCR在更多菜单执行。开启穿透前展示恢复入口并检测菜单栏入口可用；开启后主窗、菜单栏及配置的全局热键均可关闭穿透。“恢复浮窗交互”同时恢复可见底板与工具栏，避免透明+穿透组合使窗口无法找回。不能仅靠鼠标悬停一个不可点击区域恢复。
- 特殊规则：默认两个固定入口始终可恢复访问；用户扩展工具栏的自动隐藏可关闭，VoiceOver或完整键盘操作时保持可访问。长句、360pt紧凑宽度与200%阅读字号采用有限高度正文滚动，固定操作不滚动、不裁切。跟随窗口、多显示器、Spaces、全屏游戏分别显示能力原因；完整文本同时可在SCR-08阅读。

### SCR-06 实时 OCR

- 内容：主要入口是全局“框选实时OCR区域…”快捷键/菜单，从用户当前应用直接唤起目标屏幕临时覆盖层；不先进入主应用选择缩略图或添加游戏。选择时冻结待定位画面，矩形外暗化、内保留原画；十字准星及尺寸在指针附近反馈，边框覆盖实际识别内容。新建拖框松手即开始持续识别，不出现常规确认按钮或主应用侧栏/设置表单。“绑定应用窗口…”是次级选项，保存identity和相对范围以跟随移动。SCR-06工作页用于任务查看、配置和恢复：显示来源/范围/状态，提供暂停/继续/停止、恢复已保存任务、调整/重选、一次OCR及设置入口。多区域管理、框显隐、可选原地样式在此渐进展开，默认原文/译文送SCR-01。
- 状态：未唤起、十字准星待拖框、拖框中、松手已提交、调整边界/重选、取消、多个范围、等待稳定、识别中、翻译中、运行/暂停/已停止、窗口移动或缩放、权限待授予/拒绝/撤销、显示器断开、目标退出/身份失配、黑屏或无图像、图像/文字未变化、OCR失败、翻译失败、译文溢出。定位覆盖层不表示OCR已经运行；引擎和翻译服务就绪分别显示，捕获失败不能冒充“未识别到文字”。
- 交互：新建有效矩形松手即提交范围、显式切换默认持续source并开始当前实时画面采集；无效/零面积拖框不启动。冻结画面仅供定位，实现方式在platform验证后决定。Esc在提交前取消，保留旧范围/source和先前运行/暂停状态，不创建/启动新任务。调整已有范围时暂挂受影响区域，Return应用新revision并恢复先前状态，Esc取消恢复旧区域；其他区域不因调区停掉。退出选择覆盖层恢复原前台焦点。提供重选及键盘调整范围的等价操作。屏幕模式记录显示器/坐标/缩放，窗口模式记录identity/相对范围；resize、DPI变动后校正，无法确定则暂停请重选。暂停停止新增采集，继续读当前画面，停止释放捕获并保留配置；HUD/边框显隐不等于暂停。显示器断开、目标关闭或捕获失效保留范围/上次结果并提供重选/检查，不改抓其他窗口或整屏。自身选区覆盖层、HUD及原地译文均排除在捕获输入外，覆盖文本默认穿透，仅编辑边界临时可交互。
- 映射：REQ-011、REQ-012、REQ-013、REQ-014、REQ-015、REQ-016、REQ-043；验收 DES-06。

### SCR-07 编辑与文件翻译

## 6 接入与恢复的关键状态流

### 6.1 直接游戏文本接入

native接入流程为：选择原生进程→检查架构与当前系统条件→检查bridge/规则能力→用户执行连接→bridge握手→引擎及文本流发现→用户选取文本→处理预览→正式翻译。compat_windows补充流程为：选择游戏/bottle（无法关联时可取消确认）→用户点击连接→检查环境→Mac客户端启动同bottle PE helper→版本/目标身份握手→连接Windows目标→等待文本→选择文本→正式翻译。两条路径使用同一application命令与状态投影；每一步成功只代表该步骤，“游戏启动”“helper就绪”“连接成功”“发现文本”和“可以内嵌”不能合并成一个绿色状态。连接期间目标退出，返回可重新选择状态并保留检查记录。

连接失败给一个可采取的操作和必要诊断：目标退出可刷新，协议版本不匹配可打开更新，未知引擎可查看兼容性和选择OCR/剪贴板；helper失败可重试或修正bottle并查看诊断，备用手动启动由故障帮助引导。取消只取消本次接入，断开清理自有helper/agent，不终止游戏或整个bottle；不能把wineserver kill作为断开动作。对系统保护阻止的情况，显示限制依据与被阻止操作，不给一键关闭系统保护的产品按钮。

### 6.1.1 Windows x86/x64自动架构路由与恢复

用户只选择游戏、执行环境和bottle。实际Game.exe的PE架构由应用读取，不按Mac CPU、Wine进程架构、launcher位数或已有库名猜测；x86目标采用helper64/Host64接收、同源injector32/Hook32，x64目标对应injector64/Hook64。32位范围只覆盖目标侧游戏接入，不新增32位OS或主客户端支持。Host/injector/Hook名称与文件hash属于高级诊断及报告，不能转化成要求用户拼装组件的表单。

| 状态 | 页面反馈与动作 | 取消 / 恢复约束 |
| --- | --- | --- |
| 检查中 | 保留目标与bottle，显示当前阶段；不伪造百分比或启动成功 | “取消检查”及Esc可用；不终止游戏 |
| 缺32位资源 | “缺少32位连接组件”，注入尚未开始；修复同源资源包、重新检查或OCR | 取消不改旧配置，资源完整校验后才能再连接 |
| 架构/版本/hash组合不符 | 明确“已阻止错误组合进入游戏”，高级诊断定位实际与期望 | 不尝试错误位数LoadLibrary；修复后新检查，不能沿用旧ready |
| 注入前取消 | 已取消，保留目标、bottle与专用配置 | 重试创建新scope/epoch，不接收旧握手 |
| 注入后取消 / 超时 | 先失效会话和token，检查detach/卸载回执；未确认时显示目标内状态未知 | 接收端退出不代表游戏内组件已卸载；保留诊断，重连前检查，不关闭整个bottle |
| 组件就绪但无文本 | 连接与取文分别为未验证/等待实际事件 | 可检查候选流或转OCR，不显示游戏支持成功 |

`compat-x86-v1`复用既有DesignStatus、DesignKeyValue、原生DisclosureGroup、按钮与表单间距；连接sheet与高级诊断原生可编辑。8张样张覆盖SCR-03配置1张、SCR-04检查浅深色/缺资源/错误组合/取消5张、SCR-22报告浅深色2张。固定memo01原包候选身份仅供理解目标，并不构成实测；Never7的x64观测不能代替x86，Ever17修复版不作为原发行GC验收。设计导出与视觉检查记录见[compat-x86-v1 QA](../design/compat-x86-v1-qa.json)，真实组件构建、跨位数通信及游戏接入仍NOT_RUN。

### 6.2 无游戏实时OCR翻译

US-10从“框选实时OCR区域…”直接进入SCR-06，以现有SCR-01/06/14组成完整流程，服务与快捷键仍在SCR-15/18设置；不新增screen、不先引导添加游戏或连接HOOK。首次启动的等待输入HUD与菜单入口就足以发现此流程；选取范围、模式与权限用途在执行捕获时解释，避免用户把捕获目标窗口与翻译浮窗混为一谈。权限在需要使用时请求，符合[Privacy](https://developer.apple.com/design/human-interface-guidelines/privacy/)的按需授权原则；以下命令布局和运行语义是本产品的设计决策。

| 环节 | 可观察呈现与操作 | 运行语义 |
| --- | --- | --- |
| 进入与选择 | “框选实时OCR区域…”全局快捷键/菜单从其他应用直接唤起目标屏幕临时覆盖层；冻结定位画面、十字准星、尺寸，拖框外暗内原画。有效矩形松手即提交并开始，Esc在提交前取消；不先打开工作页或选择捕获模式。窗口绑定为次级入口。 | 无游戏上下文使用全局配置；新建取消保留旧范围/source及原运行/暂停状态，不创建新OCR任务。屏幕模式固定坐标读取当前可见画面，窗口模式跟随同一identity；定位冻结图不是持续识别输入。 |
| 准备与开始 | 松手提交范围时检查捕获权限、OCR引擎与翻译配置，首次必要时请求系统权限；缺项给具体修复入口，不另加每次确认或回主窗口点击开始。覆盖层退出恢复原前台焦点，工作页仅供任务查看、配置和恢复。 | 有效提交将默认持续source切为OCR，捕获限选定范围并排除选区层/HUD；要保留HOOK应另用“一次OCR…”。权限、安装、runtime就绪与实际识别分别判断，失败不虚报已开始/已翻译。 |
| 识别到展示 | 区域状态为等待稳定/识别中；取得原文后SCR-01即显示原文，译文位置显示“翻译中”，返回后更新同句译文。来源在更多/历史可查，状态13pt可读。 | 图像稳定判断与识别文本去重分别执行；动态背景不使同一文字反复请求。每个范围独立处理，最新文本与当前译文绑定，迟到旧结果不得覆盖新句。 |
| 常驻与后台 | 用户pin置顶，在游戏/浏览器/视频前台仍阅读HUD；主窗口可关闭，OCR状态仍可从菜单栏查看。全局显隐快捷键隐藏/恢复当前HUD，不激活主窗口。 | 周期/图像更新模式按捕获能力后台运行，事件模式限绑定目标前台；隐藏HUD或边框不停止采集/翻译。用户暂停持续可见且不因失焦、显隐或唤醒自动解除。 |

### 6.3 浮窗显隐与交互恢复

常驻浮窗与采集状态独立：pin选择由窗口实际置顶结果确认；全局显示/隐藏命令只切换可见性，恢复显示当前文本/译文，OCR和直接游戏文本源不因此停采集或重连。常规pin在其他应用前台保持，若全屏/Spaces受系统限制显示具体原因。首次运行提供可见、可交互的等待输入HUD；第一期交付包含这个真实应用窗口、pin及可在目标应用前台触发的显隐快捷键，基础HUD与GC/GN共同通过才允许GE放行，GU完整四页的其余验证在GE后补齐。完整实时OCR流程按D2验收，见[开发分期表](05-development-plan.md)。

浮窗穿透的关键路径为：确认恢复入口可用 → 开启穿透 → 显示持续状态 → 用户从菜单栏/主窗/全局热键执行恢复 → 底板与工具栏可見 → 返回可交互模式。应用重启、崩溃恢复或配置导入后，首次展示浮窗使用可交互、可见状态；不能自动恢复成无法找到的透明穿透窗口。
