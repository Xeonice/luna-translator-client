# 模型与翻译服务配置：产品需求

当前完整设计组合（guided与R79历史页）已由用户明确审核通过，身份见[源版批准记录](../development/design-approval-complete-20261031.json)；其他页面按[全页与状态闭包](../development/all-page-design-coverage.md)逐项对齐。设计源批准、独立参照、真实组件和正式包验收分别记录；原29个阅读/配置增量状态继续保留，不能代表整套页面。

现行呈现以第10章的必要配置引导和第8章的浅层选用为准，底层资源、版本和用途合同保持。目标为[guided完整稿](../design/first-product-v1/candidates/guided-service-reading-20261030/index.html?scenario=settings)，源版本已获用户审核确认；当前源码与目标差距见第11章，不据此声称所有服务已接通。

本稿属于[AI 阅读与学习 PRD](ai-reading-prd.md)，细化原 REQ-020～024、027/028、049/050、052/054。原56项需求、优先级及产品快照保持不变。本稿定义产品行为与验收，不表示已实现、已测试或已经支持某家服务/模型。

## 1. 用户目标与范围

用户可以配置自己的云端、本机或远程模型服务，为翻译、句子精读、语境查词分别选择模型及请求策略，清楚知道哪些配置生效、哪些用途可用、何时会发送文本。

首期须提供完整的“配置 → 保存草稿 → 可选样句测试 → 明确选用（学习用途独立应用）→ 独立启停 → 实际使用 → 修改/停用”的闭环；这些动作分别处理，保存或测试不会选用或启用。比较译文、学习草稿、历史问答沿用相同配置体系，但在对应场景交付前明确为规划能力，不显示成已可用功能。

基础分词器与词典随客户端内置。大模型是独立服务配置；本机模型连接不代表应用已安装推理服务或模型权重。

### 1.1 全量协议与注册范围

本批一次纳入13协议与21个服务/接口预设，完整矩阵见[主技术稿第5章](../architecture/japanese-study-and-llm.md#5-翻译引擎与模型服务设计)和[机器目录](../architecture/model-service-registry-design.json)。不以现有三协议切片缩减该范围。

- 模型协议：OpenAI Chat、Responses、Anthropic、Gemini原生、Ollama原生、LM Studio原生。
- 翻译协议：Azure Translator、DeepL、Google Basic v2/Advanced v3、百度、有道、TokenHub专用翻译。
- 腾讯旧TMT/TC3及其专属认证、预设和专项验收明确排除；TokenHub Chat（复用Chat协议）及专用翻译保留。

服务厂商与协议分开：一个厂商可有多个明确接口，同协议可有多个厂商。协议/profile/厂商三层注册产生同源目录；不能据兼容接口可用宣称所有原生接口可用，失败也不自动切协议。单Key、多字段签名、OAuth/刷新与安全存储均是本批前置，不因缺账号/Key将目标移到后续。

传统翻译只允许translation用途；没有模型ID概念时不要求虚构ID。LLM的translation/grammar/context_word独立绑定并按模型实测，协议、模型发现、结构化JSON和学习质量分别验收。保存/导入仍不外发；用户显式测试、应用和启用后才使用。

上述为本期交付范围，不表示13协议已经接通。当前三协议源码与未完成目录、接口和认证能力在第11章及主技术稿分别标明；缺服务前提写blocked，未执行写not_run，不能以移除条目、示例数据或旧回执替代。

本机非大模型翻译采用第7章的独立引擎配置，不受HTTP地址、模型ID、API Key字段约束。它与本机Ollama/LM Studio等大模型服务是两类执行方式；专用NMT可能仍需语言模型包，但不以部署通用LLM为前提。

## 2. 三层配置及关系

这些关系定义应用必须维护的信息，不构成要求用户逐层创建技术实体的表单流程。用户入口按第10章从用途与品牌开始，字段按所选服务适用性出现。

| 内部对象 | 必须承载的信息 | 关系与呈现约束 |
|---|---|---|
| 服务连接 | 名称、协议、云端/本机/远程位置、服务地址、认证引用、网络设置 | 一个连接可供多个模型配置复用；名称可由服务生成，固定地址由目录提供；新建不自动接收台词 |
| 模型配置 | 所属连接、实际模型 ID、显示名、能力、默认参数、模型专用模板 | 同一连接可配置翻译和解释模型；仅适用模型的服务要求实际ID，显示名不替代请求身份 |
| 用途绑定 | 场景所选配置、模板、上下文、语言与运行策略、是否启用 | 翻译、句子精读、语境查词独立绑定；可显式共用资源，不要求用户理解底层引用 |

用户可只配置翻译，暂不配置其他用途。配置同一个模型供两个用途使用，不会共享二者的原句、历史范围、请求状态或结果。

## 3. 可追溯需求

AI-CFG 编号保留原 REQ 追溯。每条“验收”定义产品必须达到的结果；[模型配置验收矩阵](model-configuration-acceptance.csv)保留not_run计划定义，实际执行另建回执，不能由源码存在或文档更新回填通过。

### AI-CFG-01 服务连接

提供新增、命名、编辑、复制和停用连接的能力，通过服务配置任务入口呈现，不要求用户先创建连接实体。协议适配器、服务地址、部署位置、认证方式及凭据引用由对应目录与适用字段承载；高级网络项包含代理继承/覆盖与必要的服务自定义项。协议选择与模型选择分开，首期选择范围见1.1。

地址校验区分缺项、格式和不适用协议；可预览脱敏后的实际目标地址，避免自动重复拼接路径。未支持的协议可保存为草稿并说明原因，不能假装能够调用。服务目录可更新，不把某一家账号或某个模型预设为用户已有。

验收：两个不同地址/协议的配置互不覆盖；保存连接不发请求；编辑地址后旧测试标为需重新测试，其他用途配置不丢失。

服务/协议/认证字段来自Rust同源目录。选择厂商预设后仍明确展示所选协议及版本；同厂商多接口不自动切换。未安装版本可读历史并显示不可执行；未知协议在取凭据与联网前拒绝。

### AI-CFG-02 模型选择与模型列表

每个模型配置引用一个连接，分别保存实际模型 ID 与显示名。支持刷新模型列表、搜索/选择和手填 ID；列表不可用、未实现或未返回某模型时，手填仍可保存和进行实际请求测试。刷新失败保留原选择，不静默改成列表第一项。

能力信息注明来自协议/文档、用户声明或实际测试；不能仅因列表出现就标可用。模型版本/ID 原样可查，不因服务列表变化自动切换版本。

验收：服务可达但指定模型不存在或无权限时，模型状态明确失败；列表失败不阻止手填；显示名修改不改变请求模型身份。

### AI-CFG-03 用途绑定与启用

翻译、句子精读、语境查词分别选择模型配置、模板和策略，并分别启用。新增/测试连接不自动分配用途；设置翻译也不自动启用文法。共用连接、共用模型均须在有效配置中可识别。

翻译保留原REQ-024的多引擎：可选多个传统/LLM配置，逐项启停并设置结果顺序，各自显示来源、进度与失败，受用途总并发限额调度；一个引擎失败不取消其他结果，多结果不等于回退。精读和语境查词每次任务各用一个明确绑定配置；更换配置后重试形成独立结果，不混合回答。翻译全部关闭时原文继续。

翻译用途配置语言方向、输出顺序及自动翻译行为；精读用途配置解释语言/深度、结构化或明确的纯文本解释模式；语境查词用途配置选词与所属句输入、解释语言和允许附加资料。传统翻译接口仅分配给它实际支持的翻译用途。

验收：同连接不同模型可分别完成翻译与解释；只配翻译时其他用途为待配置，不自动借用翻译模型；禁用某用途不影响其他用途、字幕或内置词典。

### AI-CFG-04 保存、测试、应用、启用相互独立

草稿允许尚缺模型、凭据或用途，断网也能保存和重启恢复；保存仅做本地校验，不触发网络、样例翻译或后台分析。无效字段定位到问题，未完成草稿不能冒充可运行配置。

保存形成配置版本。已启用用途继续使用已应用版本；用户明确“应用”后才切换。首次启用包含对所选版本的应用，列明将使用的服务和输入范围。编辑后的未应用状态须可识别；重启保留最后已应用版本及另存草稿，不自动用新草稿替换。

启用检查必填项、凭据引用和已知能力冲突。未做网络测试时标“未验证”，不标成功；允许用户显式启用本地校验通过的配置，实际调用继续按用途契约检查。已知不支持所需输出的配置须先改模式或换配置。

验收：断网保存不完整配置成功且无外发；保存不改变在途请求或正在用的模型；测试失败仍可保存；启用与应用均有明确影响范围。

### AI-CFG-05 测试分层与状态

测试由用户主动触发，预先说明测试的对象、样例和用途；默认用自造样例，不取游戏当前句。用户主动选择用当前句测试时，固定并显示发送范围。测试可能产生服务用量，结果只属于测试记录，不进入游戏正文/解释历史。

分开记录：本地配置有效性、连接/认证、指定模型实际请求、指定用途实际请求。协议没有独立健康接口时，不编造“已连通”，说明实际完成了哪种请求。成功记录包含服务、模型、用途、参数/模板版本、时间与所测试凭据范围。

状态至少包含草稿、未测试、测试中、通过、失败、需重新测试和已停用；启用/未启用是另一维度。修改影响请求的字段后保留旧结果供追溯，并标旧结果已过时。单个密钥通过不表示整个密钥池通过。

验收：连接成功、翻译成功但文法输出不合格时，不能显示所有用途均可用；测试超时/取消保留草稿，不影响运行中的字幕会话。测试只覆盖明确保存的来源、用途、输出模式、样句或固定词句及实际使用的凭据；部分密钥显示已测数量，不能显示全池通过。相同操作重试在联网前重放原结果；取消/超时不会清除同一请求范围既有的通过或失败。关闭调用窗口与显式取消分别处理，退出应用须确认在途工作及终态已经收尾。

### AI-CFG-06 能力与输出模式

能力按具体协议、模型和用途记录，覆盖文本翻译/解释、流式、结构化输出、模型枚举、用量信息、上下文限制、参数和取消语义；未知与不支持分开。兼容地址或同一品牌名称不能代替实际能力检查。

结构化文法必须校验最终输出结构和原句引用后呈现；只有普通文本能力时，可由用户明确选择“文字解释”，不绘制声称精确绑定的文法高亮。格式错误、拒绝、截断、流中错误分开处理，不静默当作完成。模型没有授权执行文件、进程、Shell或任意网络操作的用途。

验收：模型列表、HTTP成功或合法JSON都不能单独让文法测试通过；翻译专用配置不自动获得解释能力；纯文本模式始终标明其输出边界。

可用性取协议硬能力、compatibility profile、模型声明及实际用途测试的交集，并保留supported/unsupported/unknown与来源。TokenHub翻译模型不能因厂商支持其他协议就自动开放Responses/Anthropic或学习用途。

### AI-CFG-07 提示模板与变量

提供按用途区分的内置模板，可复制、自定义、恢复默认并保留版本。模型专用模板须匹配所选配置；system/user、prefill等选项按能力提供，未支持时说明。用户查看的是简明提示及预期输出，不请求隐藏思维链。

保留原REQ-023的Hy-MT2、Index-Translate、SakuraLLM/GalTransl等专用模板目标，适配档记录来源版本、适用模型/格式和语言方向；未完成适配时标未支持。换模型后不静默沿用不兼容模板；已知错配在应用前定位。未知手填模型可保存、自定义并显式测试，不能因名称相似自动宣称模板兼容。

变量目录包含当前原句、选词/词元、源/目标语言、已允许历史、匹配术语及用户选择的词典资料。翻译原文不包含ruby注音或词性色彩。未知变量和缺少必需变量在测试/应用前定位；可保存未完成草稿。无匹配术语时移除空占位内容。

用途必需的原句身份、输入范围和输出校验由应用维护，自定义模板不能覆盖这些约束或扩大发送范围。提供脱敏的有效请求预览，说明每段材料来自哪里。

验收：改模板不改原文；模板副本互不覆盖；无术语、零上下文、未支持prefill及非法变量均有明确结果；预览不含凭据。

### AI-CFG-08 参数与扩展字段

参数至少考虑输出长度、温度、top-p、停止条件、惩罚项及模型支持的推理相关选项。每层每项只有三种状态：继承上一层、显式设置、省略发送（使用服务默认）。“关闭参数”与“使用服务默认”是同一省略状态，阻断上一层显式值；不是第四种模式，也不等于发送0或空值。模型默认层的继承落到适配器默认，最终省略的字段由服务决定。可用范围与互斥关系按适配器/模型说明。

例如模型温度0.2、全局用途0.7：游戏选择继承则请求发送0.7；游戏选择省略则不发送温度；游戏显式0则发送0。请求预览显示最终状态及其来源。

不支持的参数须显示影响，用户禁用/修改后再应用；不能悄悄丢弃显式配置。自定义键值有类型和有效请求预览；请求身份、模型、凭据、用途输入范围和输出校验等保留字段不允许通过自定义参数覆写。升级映射时记录变化，不永久照搬旧参数。

验收：参数关闭后确实省略；0值与未发送可区分；非法类型/互斥项在应用前发现；换模型后不兼容参数保持可编辑而不悄悄生效。

自定义options须通过精确profile的schema/白名单；字段映射是已实现的受控规则，不是脚本。参数不能覆盖协议、模型、认证、route、工具调用或输出归属；profile更新不重解释已应用配置。

### AI-CFG-09 上下文、术语与输入范围

用途分别配置上下文：仅当前句、允许的近期原文、译文或双语，条数可为0，并有总预算。翻译可附游戏术语；精读/语境查词可附所选词法和辞书资料。历史问答以后仅使用用户明确选择的范围，不因模型窗口较大自动上传全部记录。

超预算优先保留当前分析对象、用途必需材料和明确的术语，按规则删除最旧历史并展示实际范围；当前对象仍超限时说明，用户选择缩短或更换配置，不静默截掉它。计数来源不精确时注明估计。上下文随游戏/会话隔离，重置/读档后的范围可解释，重置不删除历史。

验收：零上下文不附历史；切游戏不会混入旧记录；请求预览与实际材料范围相符；外部文本、辞书或术语内容不被当成可执行的系统命令。

### AI-CFG-10 默认、游戏覆盖与复制

服务连接和模型配置作为可引用资源管理。用途的有效值按“模型默认 → 全局用途设置 → 游戏用途覆盖”解析；游戏可继承或覆盖用途绑定、模板、参数和上下文。显式关闭不回退为继承；清空可选内容与恢复默认是不同动作。显示有效值来源。

这些资源及草稿、测试、已应用版本均归属当前配置档；原REQ-049的配置目录/多实例隔离继续保留。切档前保存编辑并说明影响，取消旧档排队/在途任务；待分析词句保留为待用户操作对象，不自动发送给新档。新档按自身已应用绑定和启用状态工作，不能挪用旧档测试或游戏覆盖。并行实例不得相互覆盖配置；跨档共享凭据引用须明确选择，不能因系统存储中存在密钥就自动关联。

复制模型配置产生独立参数/模板副本，并说明仍引用哪个共享连接。复制完整服务配置默认产生独立连接和模型配置；复用已有凭据须明确选择，不能无意公开密钥。编辑共享连接前列出受影响模型/用途；对运行用途的变更仍经应用。

验收：两个游戏各自覆盖互不串用；恢复继承不会悄悄删除用户保留的自定义草稿；复制后编辑的独立字段不影响原件；共享部分可识别。

### AI-CFG-11 凭据与多密钥

支持无认证的适用本机服务，以及适配器声明的认证方式。凭据由系统安全存储或独立安全引用管理；常规配置、日志、请求预览、诊断和导出不保存明文密钥。可以替换、移除或复用凭据引用，不回显完整值。

替换密钥或修改池成员/策略形成独立凭据/池版本，旧已应用配置仍引用旧版本，不原地改写；明确应用后才切换，相关旧测试标过时。在途任务冻结凭据版本和实际所选的脱敏Key身份。删除、锁定或主动撤销凭据立即阻止受影响的新请求并取消在途，不等待应用；旧版本是否已被服务撤销不能由客户端保证。保留旧版本仅在系统安全存储中进行，不写入历史/配置导出；不再被已应用配置或在途任务引用的旧凭据按保留策略清理。

保留原REQ-021多密钥轮询/错误权重需求：密钥池是显式配置，显示每项脱敏身份、独立测试状态及调度策略。默认使用用户选定凭据；只有启用池策略后才按其规则选择。认证失败与限流/服务故障分开处理，尊重退避和次数上限，不能无界换Key重试。不要把密钥轮询写成换供应商或换付费模型的授权。

验收：复制/跨设备导入不冒称凭据已解锁；一个Key通过不提升未测Key状态；移除共享凭据须列出受影响连接；历史仍保留脱敏来源而非密钥。

多字段签名与Google OAuth/IAM均纳入本批。普通配置只保存typed凭据/授权引用。OAuth授权身份与token材料版本分离，刷新/轮转不换主体或扩大scope；撤权立即阻止受影响任务。新增授权/秘密输入界面需补当前整稿状态并实机验证。

### AI-CFG-12 超时、并发、重试与回退

各用途独立配置超时、并发、排队/合并策略及重试上限。初始产品默认每用途1个在途请求、超时60秒可调整、自动重试关闭；这些是待实机验证的配置默认值，不是性能保证。持续翻译可丢弃未发送的过时队列项；用户已固定的分析对象不因新字幕到达被替换。

可见取消与停止新请求；取消不保证服务不计费。用量未返回时显示未知；可选预算有来源/时间范围，不假装实时掌握供应商余额。重试和回退只有用户显式配置后才启用，列明替代服务/模型、触发条件、输入范围和次数；默认不从本机切云端、换付费模型或扩大历史。

验收：超时/429/中断不产生无限请求；文法请求不阻塞原文或翻译；未配置回退时保持原服务错误，配置了回退时结果明确标实际来源。

### AI-CFG-13 应用、停用、删除与在途任务

实际请求冻结用途、配置版本、服务/模型、凭据引用和词句身份。影响路由、请求内容或权限的应用操作使旧排队任务失效，取消在途旧任务并停止显示后续片段；主动取消结果不再写正文/解释历史。普通显示名修改不改变有效请求身份。仅因换句迟到而未取消的有效结果可写原历史，不能覆盖当前句。

连接有独立可用开关；模型配置没有额外的启用开关，由用途选择。停用共享连接立即阻止所有依赖用途的新请求并取消其在途，保留用途绑定与原启用意图，同时显示“因连接停用而不可运行”，不能仍显示有效启用。重新启用连接时列明将恢复的用途并由用户明确恢复，使用各自已应用版本；保存/测试不恢复。新建连接默认不运行，首次为用途启用时须明确应用连接及用途的相关版本。

停用立即阻止新请求并取消该用途在途任务，不必等待“应用”；字幕和本地词典继续工作。删除连接/模型前列出引用与影响，用户选择改绑、停用相关用途或取消删除；不产生看似启用的悬空引用。删除配置不默认删除阅读历史，也不移除其他连接仍使用的凭据。

保留原REQ-024的缓存/人工记录复用：有效配置、模板、语言方向、处理规则、术语及输入范围版本参与缓存匹配；变化后旧缓存不冒充新配置结果，旧历史仍可查看。显示实时、缓存或人工修正来源，可配置人工修正优先级；后台结果不覆盖人工内容。重译可明确绕过缓存，并使用当前已应用配置生成独立结果。精读/查词缓存还须匹配其用途、所选词句版本和资料范围。

验收：流式过程中换模型/模板/Key策略不会让旧结果冒充新设置；关闭用途后不再发送队列请求；历史保留原配置来源，不自动重译。

### AI-CFG-14 本机、远程与模型部署边界

连接明确部署位置及实际请求目标；“本机”标签按实际地址与路由判断，不只依赖用户命名。首期接入用户已运行的兼容服务，提供状态/部署帮助；配置产品不自动安装运行器、下载权重或开通付费资源。

本机服务停止时提供恢复/测试入口；远程地址可修改并重新验证。运行器协议、模型任务能力、模型权重来源/许可分别记录。资源下载是否联网与推理请求是否离开本机分别说明；调用去向不明时不标“完全离线”。

验收：本机服务不可达不会悄悄切云端；一个运行器支持的接口不提升全部模型/用途能力；修改远程地址后旧测试失效，草稿仍可保存。

服务目录按协议contract/profile/preset三个版本读取。预设变化不改用户实际地址或模型。导入user.*非秘密JSON仅产生新预设版本及连接草稿；不注册代码，不关联已有Key，不发请求。无效导入只拒绝该导入，不能影响应用启动。

### AI-CFG-15 持久化、导入导出与升级

保存草稿、已应用版本、用途绑定、游戏覆盖、模板/参数、测试范围及状态；配置有schema版本。导出默认仅含配置和凭据引用，不能勾选导出明文密钥。跨设备导入须重新关联凭据并明确重新启用，不能自动请求游戏文本。

导入提供冲突与不支持字段预检，先备份再整体应用，可回退；不执行导入脚本。旧版本字段/能力不支持时保留可解释记录，不默默丢弃。更新后不因目录或内置预设变化切换用户模型。

验收：重启不丢草稿/已应用版本；失败保存或迁移不破坏旧配置；无法解锁凭据时用途显示待处理；旧历史与其配置来源保持可查。

跨设备预设/配置导出不包含Key、vault/pool引用、refresh token或授权grant。导入分结构、目录引用、字段与endpoint语义校验；缺协议版本明确待处理，不退回latest。新配置的adapterBinding冻结行为身份；旧格式按固定legacy codec读取，不重写历史seal。

### AI-CFG-16 首次配置与从阅读返回

从服务设置可独立完成配置和样例测试，不要求连接游戏。从文法/词卡入口发现用途未配时，保留所选词句和上下文快照，进入对应用途配置；完成后用户明确开始该任务，不自动发送其他历史。

只启用翻译也可以完成正常阅读；其他用途继续显示待配置而非伪造结果。错误入口能返回原阅读对象，配置流程不暂停或重启Hook会话。六个AI场景的绑定状态可查；未交付用途标规划中，不出现可执行的空入口。

验收：首次进入未配置文法时，保存/测试/启用之后仍分析原选句；字幕即使推进也不改分析对象；用户取消配置不丢原文或草稿、不自动调用服务。

## 7. 本机非大模型翻译（OT）

本节规定本机非大模型翻译。引擎、运行路线与资源仍属待完成合同，不据此直接安装引擎、引入生产Python、修改DDL或宣称真实离线翻译可用。既有13个HTTP协议、21个HTTP预设和TMT排除不变；AI-CFG-01～16标题、MC-01～22及FP编号保持。

### 7.1 分类、范围与入口

设置内的翻译服务管理以统一列表和类型标识区分“在线/HTTP服务”和“本机离线翻译”，选中服务后在同页编辑适用字段；不再按类型切换整页。复用现有设置窗口、表单、Select、草稿/应用与用途资源，不新增常驻设置类别。[当前完整稿](../design/first-product-v1/candidates/guided-service-reading-20261030/index.html?scenario=settings)复用既有材质与旅程；候选不继承批准图或历史实测。

| 候选ID | 用户名称与执行方式 | 需要核对的本机条件 | 当前交付状态 |
|---|---|---|---|
| apple_translation | Apple系统翻译；platform_native | macOS/SDK、传统翻译策略、所选语言对的系统可用性与语言包授权 | 候选设计；产品not_run |
| argos_translate | Argos专用机器翻译；local_worker候选 | 受审运行路线、分句/分词/推理全链路、语言包及直达/中转路径 | 候选设计；生产Python与新运行库未批准；产品not_run |

四项只提供translation；不出现在grammar/context_word的可选引擎中，导入或旧配置强行绑定时在应用/测试/执行前明确拒绝。基础词典和MeCab语言worker继续独立；离线翻译没有配置好时，原文、分词和本地查词继续可用。

“本机离线”指翻译推理路线；语言包准备可能联网，系统可能有独立使用量遥测，均不据名称承诺整机零网络。只有对选定安装、语言对和运行环境完成真实断网翻译后才显示该范围已验证。开源不等于语言包免授权，用户已有商业软件不等于本产品有分发权，四候选均不预先标“免费”“随包内置”或“已兼容”。

### 7.2 独立配置与条件字段

新增独立OfflineEngineConfig资源，由翻译用途的有序引擎项引用；HTTP继续使用既有Connection/Model路径。界面可以使用统一“引擎配置”表述，不为没有模型ID的引擎创建虚假模型，不以空URL/API Key充数。资源安装与配置启用分别表达。

| 字段组 | 需要表达的内容和条件 |
|---|---|
| 通用 | 显示名、具体引擎、执行方式、当前配置档、草稿/已应用版本、配置可用意图、引用用途与有效来源 |
| 语言 | 明确源/目标语言及简繁体；从所选引擎实际探测得到supported/unsupported/unknown，不由产品列举推断已支持 |
| Apple | 系统/API可用状态、传统翻译策略、语言对状态（已安装/可下载/不支持/未知）、上次检查时间；无需安装路径、模型ID或Key |
| Argos候选 | 运行路线的可用/待评审状态、用户选择的语言包或资源目录、包版本/来源/完整性、分句/分词资源；运行路线未实现时明确不可测试与不可启用 |
| J北京/金山 | 用户选择的安装目录、探测到的引擎/数据版本、DLL位数与worker位数、Windows或明确Bottle环境；不要求用户手拼DLL加载命令，不扫描未选择的其他目录 |
| 路径与资源 | 显示已选位置、可读性、实际资源身份、所需磁盘条件与恢复入口；目录存在不等于能翻译，移动/替换后须重新探测/测试 |
| 翻译策略 | direct_only或显式允许的pivot路径、有序结果、自动翻译、超时/并发/重试；仅列引擎真正支持的术语/参数，不展示LLM温度/提示词等无效项 |
| 测试与诊断 | 本地探测和真实样句翻译分开；显示对象/语言对/资源版本/实际路径/时间/失败阶段；无用量数据时为不适用或未知 |

安装路径只作为本机定位线索，不能代替不可变资源身份。显示资源版本、hash或系统可观察版本时要注明来源；系统不公开包版本就显示“系统未提供”，不得伪造一个可追溯版本号。

### 7.3 草稿、准备、测试、应用、启用

1. **保存草稿**只写本机配置，即使未安装、缺包、断网或路径暂时无效也能保留；不翻译、不下载、不启动持续任务，不改变当前已应用引擎。
2. **检查本机条件**由用户触发，只检查所选系统能力/安装/资源；若需启动受监督的探测worker须标明。结果只证明探测阶段，不标“样句翻译通过”。
3. **准备语言包**为独立明确操作。Apple由系统请求下载许可；其他引擎提供官方安装/资源帮助或本地包导入候选，不自动下载、不绕过授权。取消许可或离线失败保留草稿。
4. **样句测试**明确显示引擎、语言方向、实际直达/中转路径和所用样句，默认不使用当前游戏文本。执行与正式翻译走同一Rust路径；输出归测试记录，不写游戏正文/历史。
5. **应用**列出将改变的翻译用途/游戏覆盖及资源版本，原子生成已应用版本；不把未应用的其他HTTP或学习用途草稿一起启用。未知必要能力、缺资源、未实现运行路线和已知版本不兼容时不可应用为可运行配置。
6. **启用/停用**与应用分开。可运行性本地校验通过而尚未做样句测试时可以由用户明确启用并显示“未验证”；已知不可运行项不得假启用。停用立即阻止新任务并取消相关在途，保留绑定和历史。恢复须明确操作，不因保存/测试自动恢复。

字段、语言、安装、资源或路由改变后，旧测试保留并标“需重新测试”；新草稿不会影响原已应用版本。运行时发现旧应用资源丢失时阻止新派发并显示原绑定不可运行，不能悄悄使用新版本、另一语言包或云端服务。导入/复制不会取得本机路径授权或沿用通过状态。

### 7.4 直达、中转和输入边界

默认direct_only。缺少ja→zh直达资源时显示“缺少直达语言包”，不因为安装了ja→en与en→zh就自动中转。用户明确选择允许中转时，先显示完整路径、所需各跳包与质量可能变化，再应用；任务与结果保留该路径及各跳资源身份。任一跳缺失/失败保留错误，不再尝试未授权路径。

源/目标语言、语言包、分句和处理规则参与有效身份；不把简体、繁体或地区语言码混用。只发送引擎支持且用户明确允许的文本/术语，不拼装LLM提示词或假装拥有上下文推理能力。引擎不支持上下文、术语或自动语言识别时明确不适用，不能丢弃用户显式需求后判为成功。

### 7.5 失败、取消与恢复

| 可观察状态 | 用户得到的说明和恢复 | 必须保持的边界 |
|---|---|---|
| 未安装 | 所选引擎未检测到；选择合法安装或查看官方帮助 | 不自动安装，不影响其他引擎 |
| 系统/API不可用 | 指明当前OS与所需能力；保留草稿 | 不冒用同品牌云接口，不编造Mac/Windows兼容 |
| 缺语言包/语言对不支持 | 区分可准备与不支持；显示所缺路径/语言对 | 不后台下载，不自动中转 |
| 包损坏/版本不兼容 | 显示资源校验或版本阶段错误；重新选择受支持资源 | 不将目录存在当作通过 |
| 路径失效/安装被移动 | 显示已应用资源不可用；重新定位并测试/应用 | 不以同名目录替换冻结身份 |
| 许可拒绝/准备中断 | 显示尚未准备完成，可重试 | 不自动再次弹许可，不提升就绪 |
| worker卡死/崩溃 | 终止或回收自有worker，保留本次失败，可明确重试 | 有界队列/时间/内存，不能卡住UI、Hook或词法worker |
| 断网 | 已准备资源按实际离线路线运行；未准备则说明缺项 | 不转云端，不把离线失败伪装网络成功 |
| 用户取消/用途停用/配置变更 | 立即停止展示后续结果并使旧任务失效 | 引擎是否真正停止计算按能力说明；迟到不写成功/缓存 |
| 新句已到而旧请求有效 | 旧结果只能回写原句历史并显示原来源 | 不覆盖当前句，不改成新资源/新配置来源 |

多引擎的独立结果顺序、失败隔离、人工修正优先级、缓存绕过重译、全局/游戏继承以及配置档隔离沿用AI-CFG。离线引擎失败不授权其他HTTP/云端引擎接收文本。若用户另行配置回退，必须保留完整实际来源及范围，仍按既有显式策略调度。

## 8. 日常选择翻译服务与配置管理（SS）

日常选择在统一浅层位置，配置管理独立；未配置就绪的资源不可选。本章细化AI-CFG-01/03/04/05/06/10/12/13/16与FP-04/06/09/11/12，原需求标题、MC矩阵及13协议/21预设、4离线、PA与OT范围保持。当前呈现采用已批准的guided与R79组合；设计源确认与真实选用/服务执行分别验收。

### 8.1 两类任务与入口

| 用户任务 | 入口和可做的事 | 对当前阅读的影响 |
|---|---|---|
| 配置管理 | “管理翻译服务”进入设置；新增、编辑、保存、检查本机条件、指定样句测试与修复 | 保存产生资源版本，不改正在使用的服务，不自动测试、发送台词、启用或下载 |
| 日常选用 | 当前会话浅层“翻译服务”；HUD复用同一个选择器 | 点击可选项即明确选用已保存版本，为后续句创建新用途绑定；保持原翻译启停 |
| 当前句重译 | 独立的“重新翻译本句”动作 | 固定当前句及新绑定后再提交；切换服务本身不重发当前句或改写旧结果 |

日常列表统一容纳翻译用云端服务、本机非大模型引擎及LLM；行内说明类型、配置名、可用状态和来源。云端或本机位置不能代替用途能力判断，本机HTTP大模型仍属于LLM服务。精读专用配置不出现在翻译选择器，不能仅凭显示名、厂商品牌或“LLM”分类自动借用。内置厂商、协议和引擎模板目录只在“添加服务”中出现；没有添加的模板不能充当用户已有配置。

### 8.2 只有配置就绪的已保存资源才能选择

可选性由当前配置档中的已添加资源、已保存不可变版本、必填字段与凭据引用的本地有效性、显式translation能力及用途相容性共同决定。LLM依据明确的templatePurpose和能力判断，不能从名字推断。选择器仅读取已保存配置；尚未保存的编辑和草稿不参与可选结果。没有任何已保存服务时显示待配置空态和去配置入口。

| 状态 | 日常选择行为与解释 |
|---|---|
| 未添加模板 / 未保存草稿 | 不成为可选服务；说明“尚未配置/尚未保存”并可去配置，不列出整个厂商目录冒充已添加 |
| 已添加并保存但字段缺失、凭据不可用或格式非法 | 不可选，定位缺少的字段或凭据并提供修复入口 |
| 当前保存版本已知认证、用途或执行失败 / 已停用 | 不可选，保留失败对象和原因；修复或重测后重新计算，不用旧版本成功覆盖当前失败 |
| HTTP已保存、字段合法、用途支持，但未做样句测试 | 可由用户明确选用，标“未验证”；未测试与未配置是不同状态，不虚标通过 |
| HTTP请求相关字段修改形成新保存版本 | 旧测试保留并标过期；按新版本重新计算，不能挪用旧测试，也不能仅因尚未测试永久禁选 |
| 本机引擎缺资源、语言对不支持、必要能力未知或运行路线未实现 | 不可选并给出具体原因；继续第7章资源/运行route健康门禁，不能套用HTTP未验证规则放行 |
| 已保存且满足当前用途与运行门禁 | 可选；已测试记录仍明确对象、版本、用途、语言和时间，不扩展为全部能力通过 |

测试是配置管理中的独立动作，默认用指定样句；选择服务不附带测试请求。即使列表曾可选，实际选用及发送前仍重新核对资源/凭据/版本；状态已变时保持原绑定并显示原因，不静默换第一项、云端或付费服务。

### 8.3 选中即绑定，启停另行控制

点击可选服务就是明确的activate绑定意图，不再要求去深层用途页重复应用。新绑定只引用所选的已保存不可变配置及其依赖版本；保存编辑器中的新资源不能原地替换现有绑定。选择后显示“后续句使用…”及有效范围，当前句译文和历史保留当时的服务来源。

选择动作保持翻译用途启用状态及会话自动翻译开关；原来关闭时继续关闭。用户显式操作“自动翻译”开关才启用/停用对应翻译用途，启用前再次检查绑定可用性。停用阻止新请求并取消相关在途，不删除已选服务、对照顺序或历史；不影响原文、分词、词典和精读用途。

切换使旧绑定的排队/在途任务失效并执行既有取消；迟到分片不能覆盖当前句、写成功或冒充新服务缓存。已有旧结果仍保持原句/原版本；仅正常推进后未被取消且身份有效的旧句结果按原历史规则归属。取消选择器不创建绑定，不改变当前选择或启停。

### 8.4 范围、多引擎与配置往返

选择器明确显示“全局默认”与“当前游戏覆盖”，显示当前有效来源；修改全局不覆盖显式游戏覆盖。游戏恢复继承是明确操作，产生新的有效绑定；取消不修改任何范围。配置档切换仍遵守AI-CFG-10的隔离与旧任务取消，不挪用其他档资源或测试。

主翻译与对照翻译复用同一已保存服务目录。主项只有一个，对照保持有序且去重；同一配置不能同时作为主项和对照，切为主项时从对照移除。一个服务失败不取消其他结果；变更对照也不隐式开启总翻译或解释用途。

“去配置/管理翻译服务”携带来源窗口、当前游戏、作用范围、目的用途和所选服务上下文；设置完成或取消后均能返回原选择器。未保存表单保留为草稿，已经保存的资源重新进入只读投影；返回不自动替用户选用、发请求或重译，用户在选择器明确选择后才改变绑定。

### 8.5 独立验收计划

新增SS-01～12独立登记在[机器目录selection_acceptance](../architecture/model-service-registry-design.json)和[逐层测试合同](../development/translation-service-selection-tests.md)，产品状态全为not_run。覆盖同一浅层入口、已保存资源限定、禁选原因、HTTP未验证、本机健康门禁、用途过滤、保存与选用分离、后续句与启停、全局/游戏、多任务取消、主/对照去重、配置往返。设计交互与截图只能证明候选表达；真实Rust状态、原生多窗、服务调用、存储及同包四游戏仍须独立执行。

## 9. 同页管理、条件字段和独立学习

本节定义统一服务管理、条件字段与独立学习的资源规则；第10章统一规定用户流程和必要字段。配置页不使用技术实体Tab或重复日常选用入口，高级能力、历史与诊断保持可达。FL验收身份保留，不以旧表单重排代替完整guided页面。

### 9.1 统一已添加服务列表与同页编辑

设置内同一列表展示当前配置档已添加的云端翻译、本机非大模型与LLM服务，使用类型标签、配置名、保存/草稿版本及状态说明；类型不是切换整组服务的导航。内置厂商/协议/引擎模板仅在“添加服务”中展示。未配置资源仍可作为草稿管理，不因此成为日常选择器可选项。空列表提供真实添加入口，禁用项提供对应原因和修复入口。

选中一项后，同页按顺序呈现连接或本机条件、模型/语言能力、样句测试与记录，以及适用高级设置。移除原“类型 → 用途/连接/模型/模板与参数/测试与运行”两层导航，不以一组新按钮继续互斥隐藏同一表单。当前项身份、草稿与已保存版本和保存动作始终可辨；共享连接编辑影响仍按AI-CFG列明。HTTP连接/模型/用途三层资源关系与独立OfflineEngineConfig不变，不能为平铺复制业务资源或把离线引擎塞入假模型。

### 9.2 条件字段与独立学习用途

传统HTTP翻译展示协议所需地址、认证及语言字段，不展示无意义的实际模型ID、LLM提示词或采样参数；LLM展示实际模型ID、用途声明和所支持参数；本机引擎展示第7章系统、安装、资源、语言对和运行路线字段，不展示假URL、API Key或模型ID。不支持或未知的必要能力说明原因，不能靠隐藏字段绕过执行门禁。

精读与语境查词在同页独立学习用途区分别管理模型、输出模式和策略，不能借用翻译配置，也不因保存或测试翻译而启用。翻译当前服务与有效范围可查；日常选用、自动翻译启停与当前句重译继续使用第8章的浅层入口，配置页不再提供一套重复的日常选用流程。

模板、三态参数、上下文/术语、超时/并发/重试/回退/缓存及多密钥池保留在适用对象的高级区，可按需展开。折叠前可见高级区名称和已配置摘要，不能把低频能力当成无用功能删除；不同用途和服务的草稿、测试、凭据及有效来源不得串用。保存、检查本机条件、样句测试、应用与启用仍按各自业务语义分开，保存不改变正在使用的服务。

### 9.3 功能审计与验收边界

清理重复分类/实体导航、重复日常选用入口和对象不适用字段；“演示返回/模拟故障”等控制移至页外评审工具，产品表单仅保留实际可操作的配置与测试动作。不增加空按钮，不伪造成功，不删除审计、全量提取、Hook诊断或高级配置能力。会话同页三独立区遵守[RW-17～23](reading-window-session-prd.md#flat-current-session-prd)。

新增FL-01～10在[机器目录flat_acceptance](../architecture/model-service-registry-design.json)和[平铺逐层测试与功能审计](../development/flat-service-session-tests.md)独立登记，产品状态全部`not_run`。设计检查验证候选同页内容、条件字段、独立区状态、键盘与窄窗；真实组件、Rust状态、存储、系统/服务、正式包和四游戏仍需后续真实adapter与独立运行证据。旧13协议/21预设/4离线候选、PA12/OT16/SS12、MC22、RW34和153组合不修改状态或继承新通过。

## 10. 用户所需的服务配置与阅读优先（GD）

用户要求当前正文优先，历史和日志在后方按需展开；配置应是用户能理解且只需填写其所需内容的任务流程。呈现遵守本章必要字段规则，底层连接/模型/用途、精确协议、凭据、已保存资格、版本、启停和审计合同保持。当前[完整候选](../design/first-product-v1/candidates/guided-service-reading-20261030/index.html?scenario=reading)及[服务配置](../design/first-product-v1/candidates/guided-service-reading-20261030/index.html?scenario=settings)的源版本已获用户审核确认。

### 10.1 从用户任务与品牌开始

用户先选择“翻译台词 / 句子精读 / 语境查词”，再从适用于该用途的品牌或本机引擎进入配置。已有服务继续统一管理；只有添加时出现尚未添加模板。OpenAI、Gemini、Ollama、LM Studio、Google Cloud Translation和TokenHub等多接口品牌须明确选择具体接口，展示可理解的区别；不能靠品牌名推断协议，不能遇错切换接口或供应商。选中精读/查词不借用翻译绑定，不默认启用或发文本。

主表单回答“填什么才可以保存并供该用途使用”：密钥、实际模型或所选服务要求的应用ID/区域/项目/授权、本机资源位置等。连接、model_config、schema、contract、revision和安全凭据引用均不作为用户必填术语；固定协议和签名参数由精确预设/适配器内部持有，状态与来源在按需详情中查。普通服务可由品牌和用途生成可编辑名称，不要求另填一套连接名和模型显示名。

### 10.2 逐服务字段目录与缺省来源

[呈现字段目录](../architecture/service-configuration-presentation.json)精确引用全部21个HTTP预设、13个协议和4个离线引擎，不增删原目录。每字段记录稳定ID、类型、中文标签、required/conditional/default/advanced/readonly/notapplicable分类、声明式条件和来源；条件仅描述呈现，不执行脚本，不替代Rust资格校验。用户实际所需字段的条件未知时必须显现输入或阻断说明，不能当作不适用放行；内置固定地址等预设资料未完成则是资料前置阻断，不能转嫁为普通用户必填。

已核官方缺省才可带入；实际模型由用户发现/选择或手填，不将文档例子和流行模型当其账户默认。地域/套餐决定地址时要求明确选择；自定义地址保留原协议/profile身份并重新验证。内置服务的固定地址由资料目录供给；尚未核准的站点/应用授权资料保持待完善或阻断，不要求普通用户代填我们的资料。只有用户明确选择自定义服务器、专属地址等真实需求时才显示相应地址输入；不用example.invalid、示例模型或空凭据冒充已配置。已有服务显示其真实已保存值，不以新目录默认覆盖用户选择。

### 10.3 密钥、高级设置与独立学习

用户看到“API Key / 订阅密钥 / 应用密钥”“已保存 / 更换 / 移除”，秘密输入默认遮罩；安全引用、池revision、刷新token等内部材料不作为表单值。正式实现仍由安全存储管理版本化引用，普通草稿、日志、预览和导出不保存明文。离线HTML只用明确标注的虚构设计输入和不透明演示引用，不收真实Key或假装完成OAuth。

模板/三态参数、上下文/术语、网络、超时/并发/重试/回退/缓存和多密钥池在当前服务或用途适用时保留高级入口与已配置摘要。不适用字段不显示；确实必需的地址、认证、模型、项目、资源不因“简化”藏进无法发现的高级区。精读和语境查词各自独立，默认折叠，仅用户需要时展开；保存/测试/应用对其他用途的影响继续明确，不能自动启用。

### 10.4 阅读与验收边界

当前原文、译文及进行中/失败/关闭状态形成独立首屏阅读卡，来源和复制/重译/学习动作就近；关联/阶段/预览为辅助。正文历史、全部提取和Hook诊断在主阅读后方默认折叠，各自数量和警告/缺口摘要仍可见；展开状态不改变三数据集的完整性和审计范围，详见[会话PRD](reading-window-session-prd.md#guided-current-reading-prd)。

新增GD-01～12在[机器目录guided_acceptance](../architecture/model-service-registry-design.json)和[必要配置与阅读逐层测试](../development/guided-service-reading-tests.md)独立登记，全部产品`not_run`。旧PA/OT/SS/FL、MC/RW与153计划保持；设计截图和浏览器交互只证明候选。200%整桌面Zoom须如实记录裁切限制，不能只凭入口/键盘仍在就宣称完整布局无裁剪。正式组件、真实认证/服务、本机条件、存储、原生及四游戏仍需后续真实adapter与独立运行记录。
