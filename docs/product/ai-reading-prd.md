# AI 阅读与学习：产品规范

本页定义首版AI阅读与学习的产品行为，配套以[当前完整设计](../design/first-product-v1/README.md)为准；guided与R79完整源版已获用户审核确认。字段、运行路线和内容质量政策按具体任务核对，不由源版确认自动批准；真实功能和产品回归分别留证，缺项保持未完成。材质依据保留在[已确认案例](../design/macos-material-case-v1/index.html)。

本稿补充“软件如何使用大模型帮助用户理解、比较和学习文本”。原 PRD 的56项需求、22屏及100文件快照保持不变。情境翻译、句子精读与语境查词已纳入用户确认的首版范围；译文对照、学习草稿和限定历史问答保留后续规划。范围确认不表示生产代码、模型调用或产品回归已完成。

## 1. 范围与职责

情境翻译、按需句子精读和语境查词依托当前阅读、历史与学习窗口，不新增通用聊天主页。用户围绕正在读的句子、选词或明确选择的历史，获得有来源、可回看且不打断取文的辅助。

业务来源保持[原PRD](original/docs/01-prd.md)身份：REQ-021～024对应模型接口/上下文/多引擎，REQ-027/028对应术语与游戏覆盖，REQ-029/030对应分词查词，REQ-032对应制卡；`EXT-AI-001`对应按需文法与句意解释。第一版和后续范围分别见下一节，不因文档整理增删。

服务如何配置、保存、测试、选择、启停和按游戏覆盖由[模型配置PRD](model-configuration-prd.md)统一定义；对象身份、调度、位置引用及模块责任见[技术设计](../architecture/japanese-study-and-llm.md)。本页定义使用场景、发送范围、结果和恢复规则，不建立第二套配置或运行权威。

## 2. 首版场景与后续范围

以下 AI-SC 编号用于本补充稿，独立于原 REQ 编号。AI-SC-01～03 属于首版设计范围，AI-SC-04～06 为后续提案；不修改原 P0/P1/P2。

| 编号与场景 | 入口与触发 | 输入范围 | 主要结果 | 关联与阶段 |
|---|---|---|---|---|
| AI-SC-01 情境翻译 | 新字幕自动触发；历史句可重译 | 当前句、允许的近期对白、游戏术语；上下文可为0 | 流式/完整译文、服务与完成状态 | REQ-021～024/027/028；首期细化 |
| AI-SC-02 句子精读 | HUD常用“分析本句文法”按钮、当前会话分析、历史句精读或词卡所属句入口 | 固定原句、词法快照、允许的上下文 | 句子骨架、助词/活用、复合表达、省略/语气及可能解释；可定位原文证据 | EXT-AI-001、REQ-029/030/045；首期 |
| AI-SC-03 语境查词 | 词卡“结合本句解释”，用户主动调用 | 选词及其所属句；需要时附允许上下文 | 本句词义、活用、搭配和语气说明；与内置释义分开显示 | REQ-030、EXT-AI-001；首期 |
| AI-SC-04 译文对照理解 | 当前句或历史中选择已有译文，点“比较理解” | 明确选中的原句与译文；可附同一上下文 | 直译/自然表达差异、可能遗漏、措辞含义；注明模型建议 | REQ-024/045；后续 |
| AI-SC-05 学习草稿 | 词卡/精读/历史句中的“生成学习草稿” | 用户选定词句与目标：例句、改写或卡片草稿 | 标明AI生成的例句、难度重述、词释/文法卡片草稿，可编辑确认 | REQ-032/045；后续 |
| AI-SC-06 限定历史问答 | 在历史选择范围，再提问或回顾 | 仅用户指定的已采集记录及其中已有资料 | 对话回顾、指代/表达问答；引用记录，证据不足时说明 | REQ-022/045；后续新增产品场景 |

AI-SC-04 不给译文编造“客观准确率”；模型比较是辅助意见。AI-SC-05 的生成句不混入游戏原文历史。AI-SC-06 不引入未选历史或外部剧情，不推断尚未阅读的路线；长篇剧情总结仍需另定范围与门禁。

## 3. 首期用户旅程

### 3.1 正常阅读与翻译

1. 用户选择输入源和正文流；原文先显示，内置分词/词典在本地工作。
2. 翻译尚未配置时进入服务设置，按翻译用途→品牌→明确接口/引擎填写必要内容并保存，可单独测试明确样句。返回统一选择器显式选用已保存且合格的服务，并单独开启自动翻译；保存、检测或返回不切服务、不自动发送游戏台词。
3. 启用的翻译用途读取当前句及允许的上下文，异步返回译文；服务异常不阻塞原文。
4. 原文和译文写入对应阅读记录，保留模型/服务与配置来源；用户可关闭翻译并继续阅读。

### 3.2 看不懂一句话

1. 从字幕常用“分析本句文法”按钮、当前会话的分析动作或历史句精读入口进入；从词卡进入时固定词卡所属原句。当前入口与窗口关系见[guided阅读](../design/first-product-v1/candidates/guided-service-reading-20261030/index.html?scenario=reading)及[完整设计索引](../design/first-product-v1/README.md)，常用分析不以打开“更多”为前置。
2. 固定该句、文本版本和允许上下文，打开独立学习窗口；字幕继续接收新句。
3. 尚未配置文法用途时保留待分析句，进入该用途的服务配置。配置保存/检测后，由用户显式选用并启用文法用途，再点“开始分析”；保存或检测不自动激活，已有翻译配置不等于已启用文法用途。往返与旧对象保留遵守[AI-CFG-16](model-configuration-prd.md#ai-cfg-16-首次配置与从阅读返回)。
4. 分析中可取消；成功显示结构与原文证据，失败保留原句并允许重试。歧义、指代和省略成分以可能解释呈现。
5. 用户主动点“分析最新一句”才切换对象；继续阅读不会偷偷替换正在看的解释。

### 3.3 词典释义不足以理解本句

1. 点击词语，先显示内置词典的词面、词元、读音、词性与释义，不等待网络。
2. 用户点“结合本句解释”；服务选择按解释用途配置，首次未配置时保留所选词句并引导配置。
3. AI 解释单列显示本句用法、搭配和可能歧义，并定位相关原文；不覆盖内置辞书字段。

## 4. 翻译与学习的服务配置

完整行为由[模型与服务配置PRD](model-configuration-prd.md)的AI-CFG-01～16、必要字段引导和统一浅层选用规则维护；[配置验收矩阵](model-configuration-acceptance.csv)保留计划，真实执行另记。本节只作用户主线摘要，不建立另一套实体编辑流程。

| 用户步骤 | 需要决定或填写什么 | 生效边界 |
|---|---|---|
| 选择用途 | 翻译台词、句子精读或语境查词 | 各用途独立选择与启用；不借用另一用途的凭据、输入或结果 |
| 选择品牌和明确接口/引擎 | 适用于该用途的内置品牌、明确接口或本机路线 | 同品牌多接口须明确选择，不按名称猜能力或失败后自动换协议 |
| 填写必要内容 | 所选服务要求的Key/应用ID与密钥、实际模型、项目/区域或本机资源；只有相应类型需要时显示 | 固定地址与签名由预设内部持有；传统/离线不填虚构模型或通用HTTP字段，未知必要条件明确阻断 |
| 保存与可选测试 | 保存草稿/新版本，明确样句和测试用途 | 保存/测试不自动选用或启用，不发送当前游戏台词，不把列表发现/HTTP成功等同用途通过 |
| 明确选用与启停 | 从统一选择器选择合格已保存版本，说明全局/游戏范围；每用途显式启停 | 后续句按新绑定执行，当前句重译/精读是独立动作；停用阻止该用途新请求 |
| 按需高级配置 | 适用的模板/三态参数、上下文/术语、网络、密钥池及运行策略 | 保留默认与来源摘要，不将内部引用/版本字段转给普通用户必填 |

底层仍复用连接、模型配置、用途绑定和不可变版本；这些关系由Rust管理，不要求普通用户先分别创建连接名、模型名再分配用途。当前源码整体Save/Apply与目标细粒度选用的差距见[整页交付计划](../development/current-client-alignment-plan.md)，不能将前者当成后者已实现。

模型发现不可用时允许按具体服务手填真实模型；本机服务不可达不自动改走云端。配置修改、取消、迟到与流式返回保留原配置和固定词句归属，凭据保护、导入导出/升级、多密钥、超时/并发/重试/回退均按专项规则验收。未配置学习用途时保留所选词句，配置后由用户启动原任务；基础分词与词典不依赖模型服务。

## 5. 所有 AI 场景共同遵守的产品规则

| 规则 | 产品要求与验收方向 |
|---|---|
| 用途分开 | 翻译、精读、语境解释分别启用和选择模型；可复用同一连接。模型发现不可用仍可手填；特定用途能力不满足时明确说明 |
| 对象固定 | 结果归属句子/词语、文本版本和上下文快照；字幕增量、切流、换模型后不把旧结果贴到新句 |
| 知识来源明确 | 本地词法、内置辞书、模型解释分别标示。词性颜色不代表已完成句法分析，模型推测不替换原文或辞书事实 |
| 按需与可控 | 翻译可自动，精读/语境解释默认由用户操作；可见所选服务和发送范围；不因悬停自动请求云模型 |
| 保持阅读 | 未配置、离线、限流、超时或取消时，原文和内置词典继续可用；保留操作对象，提供清楚的恢复入口 |
| 可回看 | 保存结果与对应原文、用途和服务来源；主动取消的请求不再写正文/解释历史。仅换句而未取消的有效迟到结果可进入原历史，不覆盖当前句 |
| 学习内容可确认 | 模型例句和卡片先成为可编辑草稿，用户确认后才加入学习库或发送Anki；不自动覆写人工内容 |
| 费用与隐私可理解 | 任务并发、上下文和重试有界；用量未提供时显示未知；凭据不回显；不会悄悄换云服务或扩大历史范围 |

基础分词引擎与词典按随客户端内置交付，首启离线可用。MeCab/UniDic 的词法数据与中文释义数据分别确定来源；模型用于上下文辅助，不承担基础词典可用性的前提。

## 6. 验收：能调用模型只是第一步

1. **真实调用与显示**：使用实际服务在最终客户端得到可见结果，配置、用途和归属可查；设计样例不能替代。
2. **句词对齐**：重复词、增量、换句、读档/切流后，解释仍对应选中的原句；文法片段覆盖正确，不能高亮不存在的字。
3. **语言质量**：以合成/授权且经人工审校的样本覆盖活用、复合文法、口语、省略、敬语和歧义，记录可接受解释与错误；JSON合法或引用不越界不代表理解正确。
4. **失败恢复**：缺少用途配置、服务中断、拒绝/截断、格式错误、取消和迟到分别验证；失败时可继续阅读并保留选定对象。
5. **后续场景独立验收**：比较意见不得当权威评分；学习草稿不自动写库；历史问答须引用范围内记录，证据不足时不得补写剧情。
6. **配置行为独立验收**：执行MC配置用例，验证离线草稿、分层测试、应用/启用、用途隔离和恢复；配置能保存或连通不等于上述阅读/学习结果已验收。
