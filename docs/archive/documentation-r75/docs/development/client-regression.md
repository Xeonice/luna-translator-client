## 四款游戏的样本口径

首轮只验证用户指定的 SR、MO、Never7、サクラノ詩 10th，**不验证 Ever17**。不因某款已进入对白、Host 已连接或收到一条事件就切换到下一款。

| 游戏 | 必须取得的正式包原文证据 | 特别限制 |
| --- | --- | --- |
| SR.exe（既有中文版） | 至少五个不同屏幕字幕状态，对应候选、原文区和阅读记录；停住后一段可读；断开后游戏仍可操作 | 如实记录中文原文；不能写成验证到日文原文 |
| MO | 至少五个不同屏幕字幕状态，覆盖跨页和停住后的当前正文 | 既往图形/内存异常未归因。记录接入前基线及异常时刻，不因能取文就宣称旧异常已修复 |
| Never7 / GameN7_Steam.exe | 至少五个不同增量文本状态，覆盖至少三个实际对白页；每状态同时映射事件与 `page_id` | 五次事件/文本状态与三页分别统计；不是五页。Steam 登录、会话冲突或缺对白保存为独立环境阻塞 |
| サクラノ詩 10th Anniversary edition | 至少五个不同屏幕字幕状态；相似候选分别对照正文质量，确认最终选择 | 两流各五事件共十事件不等于十句；同名或相似流不能合并身份或按固定索引优先 |

所有游戏采用以下统一口径：

1. `raw_event_count` 是所有原始回调数；`nonempty_event_count` 是非空事件数；`selected_stream_count` 是选中流的数量。这些都不是句数。
2. `observed_state_count` 只计算屏幕字幕发生不同变化且有对应客户端证据的状态；一次多流重复输出不能增加此数。
3. `page_count` 只计算画面可确认的对白页。逐字/增量变化属于同页多个状态；页界不明记 `unknown`，不推断一个回调是一页。
4. 游戏换行与客户端自动换行可以不同，但字符内容必须可核对。任何有意处理须记录规则 revision；不能通过全局去重或简单前缀裁剪消掉合法重复正文。
5. 按顺序保存 `G01/C01 … G05/C05` 配对画面和事件关联。允许用户手动推进 Wine 窗口；人工操作不替代自动采集与内容核对。
6. 连接后至少经历一次停止推进、客户端停在当前句、再推进以及主动断开；当前文字不能来自旧会话、静态 fixture 或历史回放。
7. M2 对四款分别再做真实翻译用例 `CR-05-SR/MO/N7/SAKURA`。原文通过不代表译文通过，也不要求未知网络延迟伪装为实时成功。

最低五个状态是首切片内容冒烟门禁，不构成完整剧情兼容或长期稳定承诺。另执行 `CR-07-SOAK`：四款分别预先选定至少30分钟或至少100次不同字幕变化的连续运行目标，保留实际时长、变化数、资源曲线与交互记录；即使选择按时间采样，也仍须完成五个不同状态的画面对照。该门禁只描述所采样范围。发布声明若包含更多章节、自动播放、快进或版本，必须追加对应场景与证据。真实游戏连续运行和十分钟高频 fixture 是两种证据，不能互相代替。

## M2-L 日语学习与大模型的执行口径

设计先使用 [日语学习交互稿](../design/first-product-v1/index.html) 评审开启后的可见效果；本轮设计示例的截图只作为后续视觉基线。实际功能检查须由最终安装包的真实分词和服务驱动，不能把 HTML 中预制 ruby、词性或解释当成后端已通过。

1. **原文与 token。** `source_text` 是不可变的真实源文本，不从 ruby DOM、渲染后的文本或术语替换结果反推。实际 tokenizer 输出的 token 加 gaps 必须逐字还原源文；word surface、lemma、reading、POS、未知词分别保存。以 UTF-8 byte span 回指，WebView 显式转换为 UTF-16 范围；覆盖汉字、空白、标点、组合字符和 emoji，禁止切断 grapheme。读音不能可靠逐字对齐时按词显示，不编造汉字级读音。
2. **内置资源与无网络首启。** 规划正式包内置 MeCab、基础 UniDic 与独立的基础查词释义；当前尚未集成生产资源。`CR-12-RESOURCE` 在干净配置、无网络和非源码目录首次启动，直接验证真实分词及基础释义，不要求下载 / 手选路径 / 安装辞书。包 manifest 分别记录形态和释义资源的来源、版本、hash、平台、许可与署名，释义来源须先选定可随包再分发的资源。完整性不达标阻塞发布，不设计常态缺词典或修复下载界面；基础辞书随应用新版本整套升级。另测 worker 崩溃、超长输入和保存失败的隔离恢复，不阻塞 Hook / 翻译，也不静默上传云端。可选扩展独立验证，日常基础能力不依赖它，原 PRD 自定义资源扩展保留 M3。
3. **屏幕归属。** SCR-01 是 HUD，SCR-09 是词卡 / 词典和本句解释，SCR-12 通用设置展开阅读开关 / 内置版本 / 可选扩展，SCR-15 是翻译及解释服务配置，SCR-18 是 ruby / POS 外观，SCR-08 可固定历史目标句。SCR-17 继续是语音，不新增第 23 个常驻导航。点词默认显示本地词法与内置基础释义；悬停或修饰键触发不得悄悄调用 LLM。
4. **不同 provider。** 翻译与解释分别配置和调度，允许同端点不同模型。传统、通用 LLM、本地 / 远程运行器是适配配置，不能硬编码某个供应商默认；至少两种协议的实际适配器和一本地运行器留真实请求证据。不支持 schema、stream、usage、模型枚举或参数时按能力明确拒绝 / 降级，接口兼容不等于所有能力相同。运行器可用不证明模型质量或模型权重许可满足分发条件。
5. **上下文与修订。** 当前句、限定历史和匹配术语的发送范围可查看，按条数 / token 双限额，不跨游戏 / 会话；原文不因术语改写。session / stream / unit / text revision / provider 配置 / prompt / 术语版本及目标句固定；快进、切流、重连、改服务和取消后迟到结果丢弃。历史句解释不偷换成最新字幕。缓存包含文本 / 上下文 hash、语言、模型、模板、术语及词典版本。
6. **AI 解释与正确性。** 本地分词只证明词法信息，不表示完整文法已分析。AI 文法项引用现存 token IDs / spans，可跨多个 token；原文省略的成分仅作推测，歧义显示备选和不确定。schema / span / revision 校验后再画文法高亮；无 schema 能力时可降级纯文本，但不画已验证引用。合法 JSON 或引用正确都不代表文法正确，实际解释须用授权 / 自制句集人工核验；不以模型自报置信度当准确率。
7. **流式、成本与资料边界。** 流中错误、HTTP 200 拒绝、截断、429、取消和超时分别留证；不完整文本不标完成，不发布未校验的文法 JSON。解释默认按需、翻译和解释云请求分别开关；并发、输出、重试、缓存及预算有限。usage 缺失标未知，取消不保证免计费。台词 / 词典 / 术语作为不可信资料，模型没有 Shell / 文件 / 网络执行工具；默认诊断不含密钥、正文、请求体或个人路径。
8. **最终包四游戏。** 新增 `CR-13-FINAL-SR/MO/N7/SAKURA` 独立执行。每款仍至少五个不同字幕变化状态，经候选 → 原文 → 实际译文 → 历史核对，再覆盖词卡 / 按需解释及失败恢复。SR 既有版本为中文，验证非日语降级，不要求生成日语 token；另行手动输入日文时记录独立来源，不能计作 SR 日文证据。MO、Never7 与サクラノ詩各保留日文学习证据；Never7 五状态至少三页，MO 旧异常及 Steam 登录等阻塞仍独立记录。

每条最终包用例的语言分支应在运行前根据实际版本固定，不能用“当前不适用”掩盖已承诺的日文学习能力。真实模型、游戏或登录条件缺失时记 blocked，先继续可独立执行的项；内置语言资源不完整则属于包的发布缺陷，不能把额外安装辞书作为正常前置；不能用设计稿、旧 Reader、原版 Luna 或 Core 探针替代。设计确认、词法内容、服务请求、AI 解释质量、视觉和原生窗口行为分别给结论。

## 接口与故障必须留证的内容

新 Core 的 Rust adapter 要先检查 `Luna_GetAbiVersion()==1`，注册七个 cdecl callback；Create 回调没有旧版 `embed_capable`。`ThreadParam` 按值 size 32、align 8、字段 offset 0/8/16/24；必须在两个实际 Rust 目标都验证。字符串只在回调期间借用，需在返回前复制。回调可能多线程且部分持锁，不能在回调同步翻译、做 GUI/磁盘/网络 I/O 或反调 Host。

Mac 原生进程不能直接加载 PE Host。首版让 Windows broker 在目标同 bottle 中加载匹配 Host，broker/Host/Inject/Hook 按验证的架构组合选择。所有文件必须绑定 Core commit、ABI、arch 和各自 hash。不能只核对 namespace/GUID，也不能把“同位数组合是首版选择”写成“Core 技术上绝对禁止其他组合”。

注入器 exit 0 只证明本次加载获得确认，尚需 Host connect、流创建和正文证据。目标身份至少包含 bottle、PID、完整映像路径、创建 FILETIME 和架构；全身份流是 PID/address/context/context2，不能只按 Hook 名称分流。

队列压力必须覆盖 callback、protocol/output、client commands、流数、Core 文本缓存、阅读/history、翻译与 API 订阅等实际启用边界。单队列有界不证明系统内存有界。至少十分钟高频 fixture 期间记录输入速率、事件大小、流基数、每个限额、内存曲线及停止/切源/shutdown 的反馈；按原 PRD，本地关键操作反馈应不超过 200ms。控制通道需优先级或保留容量，正文洪流不能吞取消/退出响应。子进程 stderr 持续读取，stdout 只放合法 JSONL。

发生 overflow、截断、解码失败或未知清理状态，必须显示并留证；`integrity_lost` 在同会话持续可见，不能被下一条正常文本清掉。当前 Core 没有可证明安全完成的 Stop/Join/卸载契约，不在存活 Host 上 `FreeLibrary` 伪装退出完成。无回执或未知 Hook 状态明确记 `unknown`。不得以停了几个进程或重开窗口作为清理干净的唯一证据。

取消、断开、游戏退出、broker 崩溃、新 PID 重启、客户端退出分别执行。只回收本次自有组件，不杀游戏、不关整个 bottle、不执行 `wineserver kill`，也不驱逐同目标的其他 owner。配套资源更新到新目录，在会话结束后切换，不覆盖加载中的 DLL。

## 可视化与原生行为分开验收

首版视觉以当前 `first-product-v1` 整稿、style-guide、共享tokens及已确认材质案例为依据，逐项保留批准范围。原 `aligned-v1`、`ocr-selection-v2`、`ocr-source-v1`、`compat-x86-v1` 的历史状态和字节不改，不自动成为当前首版批准基线。候选输出与批准截图分开，生成差异并评审后才可更新；脚本重新截图不构成确认。

Playwright捕获已实现screen的浅深色、空、错误、受限、长文、减少透明度和字号状态，以相同视口/字体/scale/数据对照当前确认设计。HUD舒适560pt/原文18pt/译文24pt，紧凑500pt/16pt/22pt，操作行32pt；注音、长文与200%字号单独检查，不固定旧132pt高度。设置按当前整稿单层导航与轻返回入口；窗口尺寸以当前设计状态记录，不从历史报告抽取旧值覆盖。M1只验适用技术范围，完整首版仍须B5全部承诺通过。

浏览器截图不能证明 Tauri 原生焦点、置顶、穿透、材质、全局热键、菜单栏恢复或全屏行为。`CR-10-NATIVE` 必须对实际发布包在游戏前台、多屏/Spaces/全屏/休眠组合另测，并覆盖长文、200%字号、键盘导航和辅助标签。缺设备的组合可独立记 blocked，不能用其他组合的 pass 补齐。

## 每次执行的证据目录与状态规则

建议本地目录 `.build/client-regression/<run_id>/`：

- `environment.json`：客户端版本、源码 revision/dirty、包 SHA-256、Core commit/ABI/arch/文件 hashes、macOS 与 CrossOver/Wine 版本、bottle 条件、目标实际版本/架构/身份。M2-L 再记录内置 MeCab / 基础 UniDic 及独立基础释义的版本、来源、许可与资源 hash、实际语言、provider 协议 / endpoint 的脱敏身份 / model、prompt / 术语与能力测试版本。个人路径/创建时间等详情仅本地保留。
- `results.csv`：沿用矩阵列，按用例和实际环境组合复制生成运行记录；增加 `run_id`、开始/结束时间、artifact hash、故障编号和证据索引。先 `not_run`，不预填 pass。
- `events/` 与 `timeline.jsonl`：M1 至少保留会话实例+event_seq、完整流身份、原始增量和生命周期；M2 再增加显示单元/revision、处理规则与翻译请求/响应关联；M2-L 追加 source hash / tokenizer 版本 / token 与 gap / span 映射及解释请求目标和校验结论。授权的正文与完整请求仅本地，不放公共报告；默认诊断仍不收集正文或密钥。
- `captures/`：游戏和实际客户端成对画面；`metrics/`：背压/内存/延迟；`faults/`：错误和现场，不先强退再猜原因。
- `evidence-manifest.json`：所有证据相对路径及 SHA-256；`summary.json`：脱敏计数、状态及局限。发布报告仅包含摘要及清单 hash，原始游戏文字、图像、日志、个人路径和密钥不随代码提交。

| 状态 | 允许使用的条件 | 不能代表什么 |
| --- | --- | --- |
| `not_run` | 尚未执行，或实现/前置尚未完成 | 不能称通过、失败或实机已验证 |
| `blocked` | 执行被具体外部条件阻断；记录原因、恢复动作、已执行到的阶段和受影响组合 | Steam/登录/设备阻塞不能写成游戏或 Hook 失败；也不能算 pass |
| `failed` | 实际执行观察到产品缺陷、内容错误、无声丢失、无限等待或不满足期望 | 不能用换游戏/忽略异常替代修复 |
| `passed` | 同一最终包及组合已完成全部步骤，有所需证据且期望满足；正常正文/闭环无丢失且关键期望已证实；故障负例确实检测、隔离并报告预期故障 | 探针、旧 Reader、其他包或组合不能代用；故障用例通过不等于该段正文无损或正常闭环通过 |

`unknown` 和 `integrity_lost` 是观察结论，不是数据完整的证明。正常正文/翻译闭环门禁必须无丢失，关键期望须有证据证实；无法证明正文完整或正常清理成功时，不得判对应的正常路径 passed。故意制造 overflow、无回执或未知 Hook 状态的故障负例，如果正确检测、隔离并如实报告预期的 loss/unknown，可以将**故障行为用例**判为 passed；这只证明异常处理符合预期，不能把故障期间的正文算作无损采集，不能借该结果通过正常端到端门禁。执行前应明确每个子场景的正常/故障期望，避免事后改期望。不存在自动 waived 或“先标 pass 后补证据”。一个组合 blocked 不阻止其他独立用例继续，但包含该组合的发布承诺不能通过门禁。

本计划不把本地证据目录的存在当成已采集；本轮没有创建运行结果/游戏截图，也没有任何新的 pass。后续提交前需单独核对实际 Git 暂存内容，保证原始私人证据未纳入。

## 执行顺序、失败处理和退出条件

1. 在写产品功能前冻结协议/资源边界，完成双架构实际 Rust ABI 与受控 callback，再验证错误资源注入前拒绝；原稿/许可 hash 保持可追溯。
2. 产出 M1 release 包并记录 hash，离开源码目录冷启动。逐款完成 SR→MO→Never7→サクラノ詩 的原文证据，一款没有拿到足够状态时先解释和修复，不把“连接了”当完成切去下一款。
3. 每款主动断开并确认游戏继续；同时执行生命周期、身份复核、选流、原始增量追溯、背压及有损提示。若外部环境阻塞，只挂起该组合并记录，不覆盖其他独立结果。
4. M1 门禁满足后实施 M2，加入阅读单元/revision、真实翻译/HUD/历史/配置；四款分别复验真实译文、迟到、网络错误、用户控制、原稿视觉和实际系统窗口行为。
5. 发现错误时先保留现场，再优先修复问题代码或恢复明确环境；修复后重跑失败用例、直接受影响链路及该里程碑关键端到端路径。更改包/hash 后，旧包结果只保留为历史，不能直接迁为新包 pass。
6. 先评审 M2-L 可见设计，M2 闭环后才实施本地词法 → ruby / 词卡 → 独立 provider / 上下文 → 按需解释，再产正式包执行 CR-12 / CR-13；重跑受影响的 M1 / M2，四游戏逐款完成。设计稿、结构校验与语言质量各自留证，不合并成一个“通过”。
7. M3 对 56 项逐项分解、实现和验收；平台/能力缺口写清 backend 依赖及真实目标。需求不能因“当前 Core 不支持”被无声删除。

某里程碑可交付的条件是：声明范围的全部门禁在同一最终包上通过，所有失败已解决并有重跑证据，所有 blocked/未验项目明确排除于本次支持承诺；修复与变更的影响面有记录。若本次声明必须覆盖四款游戏，则任何一款未验/blocked 都不能宣布“四款回归通过”。完整产品 P0/P1/P2 的结论仍分别按 `CR-11` 和原 PRD 门禁给出，不以 M1/M2/M2-L 命名取代。
