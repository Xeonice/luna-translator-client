# 正式接入独立采集与纯订阅

用户指出窗口采集应独立、其他部分只订阅，并明确指出“选中但没有改”。当前18包仅有A技术PoC，正式界面仍是旧producer：真实进程75789/77146可启动，worker权限预检允许且系统picker可呈现；首次90秒超时零帧并按预算正常reap，第二次系统选窗也超时。主窗旧路径另出现真实画面后过期。这不属于修复完成。

本变更将已规划B正式实现：一个App监督的独立worker拥有授权/核验/采集，主窗/选窗面板/封面为消费者；用户控制意图与订阅分离；临时读取故障不清可信绑定，多订阅独立取消。保留完整身份/许可/代次核验、现有公开Tauri/Core JSON合同、无图首张封面及实际签名/游戏验收。

A实施顺序修订明确记录：双PID、同签名、权限预检、系统picker呈现与超时清理已部分实证，但真实帧仍未验收。因独立PoC与旧UI并存造成用户操作落入旧路径且超时只能重开，本轮先完成统一正式控制/订阅入口，再用同源最终包补齐真实独立帧与消费者隔离。原A零帧失败不改绿；A实证条件移为B交付的硬门槛，不把测试缺口当通过，不改产品预期或放宽安全校验。
