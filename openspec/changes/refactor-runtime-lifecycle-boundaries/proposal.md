# 优先稳定性重构，再补齐产品内容

## Why
用户2026-10-26明确调整顺序：“先处理重构和文档更新，主要还要跟重构相关，解决互相影响的问题后，再补全剩余的内容”。阶段Review已确认跨层状态与生命周期交界的具体传播，并区分历史已修、当前源缺口和未验证风险。采用既有架构做内部职责收敛，不替换框架/Core，也不把所有历史问题归为同一新回归。

## What Changes
先建立SR-0～6迁移计划、四轴状态合同、不变量、影响回归矩阵及稳定性退出条件；当前阶段入口和架构/执行文档明确指向本计划。每个后续代码切片先锁原行为测试、再迁移职责、独立审阅与分层验收。剩余参数/回退/AI配置导航等产品内容延期，不从PRD删除。

## Scope
本母change仅S0文档与执行入口（kind tooling），不授权任何apps/crates/native产品源、资源、测试预期、依赖或数据库。后续每片另建窄product change与开工前快照。Root负责文档、精确基线候选与采用、HTML交付；架构/QA代理独立审阅。当前运行23、已构建24及R46历史结果不被本次文档新源码身份继承。

## Verification
现有OpenSpec、scope、基线、边界和编译检查用于校验S0资料与约束，不证明重构代码或产品已通过。状态合同/影响矩阵的业务程序化执行须在SR1维护测试中落实，正式包运行adapter及同RC原生/游戏另列。原视觉源身份失败保持，不刷新SHA/PNG/阈值。计划定义与运行结果分开；新计划不是已实施。
