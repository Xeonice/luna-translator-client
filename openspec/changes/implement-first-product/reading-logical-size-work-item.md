# 阅读字号的逻辑尺寸对齐

- 依据 FP-04/07/11、当前整稿 HUD 与词法展示、研发基线第5节：pt 表示逻辑尺寸，不直接乘设备 scale。当前设计 `#hud-source` 使用18px，译文24px。
- Owner root；M03/M05/M07，C16/C17。允许修改 SourceText.tsx、language/styles.module.css、ReadingPanel.tsx；视觉测试由 product_ui_impl 维护。保留词法跨度、查词索引、原始空白与完整原文。
- 缺陷：WebView CSS 的 `18pt` 会按96/72放大到24逻辑px；这是再次缩放，导致560宽默认HUD被多占一行。每个词的额外左右padding又改变日语排版。
- 修正：契约字号在 CSS 中一对一使用逻辑px；词语不插入额外间距，保留注音、词性、键盘焦点和命中区域。禁止改token、参考图或差异阈值。
- 验证：Playwright计算字号、200%/窄窗/长文/换行还原、词卡锚定、句末标点与同态HUD截图；原生包阅读与滚动另测。未执行项不提前填写通过。

- 同态390px窄窗实测发现独立词按钮和句末标点之间浏览器禁则不足。使用仅排版的不换行分组，把结尾标点保留在前词、开括号保留在后词；绝不跨原始空白/换行，不合并词法token，不改变查词索引。保留UI28严格坐标断言并新增混合括号/多行完整原文检查。
