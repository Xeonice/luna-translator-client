# 技术设计

1. 审查后的初始源码导入形成真实Git基线；后继CI修改通过实际PR base比较，禁止全零base回退。
2. reports、Tauri生成staging及三个大语言文件不进入普通Git；语言数据经公开CI依赖资源包按固定SHA恢复，保留许可证及原文件hash。生成staging不作为源码身份。
3. 项目Codex hook命令采用官方git根定位写法；真实L3记录实际执行源根，消费者只归一化部署根，仍验证7项源码、原始事件、实际副作用、handler/matcher/timeout；不将L1当L3。
4. CI使用代码拥有的 `--stage ci`，即使仅文档/工作流差异也强制G01～G05及完整控制测试/32组；真实产品影响继续触发G06～G09，metadata不能关闭该profile。CI冷机生成生产组件/时序/迁移/存储回执，下载固定hash的最小真实L3包，运行原统一入口及32组。G01原件的包hash通过仓库管理员变量作为外部信任锚，避免source map自引用；缺失/错hash/过期仍拒绝。
5. Actions成功后配置main必需检查，验证正常PR成功、故意越界PR失败且不可合并，保留远端原件。原生四游戏及G09产品确认保持独立未完成。
6. 现行门禁HTML、入口与阶段说明覆盖更新真实Git/Codex/远端接线；原32组计划身份不改。实施完成、非作者审核、每候选实际CI分别取证；最终文档运行回执放在树外，避免自指盖章。
